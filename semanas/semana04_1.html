1. O que é o Apache Spark?
Uma ferramenta para processar dados gigantescos muito rápido
🍕
Analogia: Pizzaria Gigante
Imagine que você precisa fazer 1.000.000 de pizzas. Com um único forno (computador normal), levaria anos. Com o Spark, você tem mil fornos trabalhando ao mesmo tempo — cada um fazendo parte das pizzas. No final, tudo fica pronto rapidíssimo!

O Spark divide um problema enorme em pedaços menores e distribui para vários computadores trabalharem juntos ao mesmo tempo. Isso é processamento distribuído.

🤔 Mas já existia o MapReduce. Por que criar o Spark?

🐢 MapReduce (antigo)
💾 Salva no HD a cada passo
🐌 Como ler um livro — pausa após cada parágrafo e anota no papel
😴 Lento para tarefas repetitivas
🚀 Apache Spark (moderno)
🧠 Guarda tudo na memória RAM
⚡ Como ler na cabeça — sem pausar, sem anotar no papel
💨 Até 100x mais rápido!
🧠
Por que RAM é mais rápida?
Pense assim: o HD/SSD é como o armário no quarto — você precisa andar até lá para pegar algo. A RAM é como a sua mesa de trabalho — tudo está ali, ao alcance da mão, em segundos. O Spark usa a mesa, o MapReduce usa o armário a cada operação!
// PERGUNTA 1 DE 3
🧠 Qual a principal vantagem do Spark em relação ao MapReduce?
🎉 Parabéns! +50 XP. Exatamente isso! O Spark mantém tudo na RAM (memória) — como deixar tudo na mesa de trabalho em vez de guardar no armário a cada passo!
❌ Quase! Pense na analogia: o Spark usa a RAM (mesa de trabalho) em vez do HD (armário). Isso o torna muito mais rápido!
💡 Precisa de uma dica?
Lembra da analogia da mesa vs armário? A RAM é a mesa — você acessa rápido sem precisar andar até o armário (HD) a cada momento.

2. Como o Spark está organizado?
Driver, Cluster Manager e Executors
🏭
Analogia: Fábrica
Pense em uma fábrica: o Gerente (Driver) decide o que fazer e distribui as tarefas. O RH (Cluster Manager) contrata e aloca os operários. Os Operários (Executors) fazem o trabalho pesado em paralelo. No final, o Gerente reúne tudo.
🧠

1
Você escreve código Python (PySpark)
O Driver recebe seu programa e começa a planejar como executá-lo.
2
Driver cria o plano de execução (DAG)
O Spark monta um "mapa de etapas" — como uma receita de bolo com a ordem de cada passo.
3

Os Executors recebem pedaços dos dados e processam em paralelo — vários ao mesmo tempo!
4
Driver reúne os resultados
Cada Executor devolve sua parte, e o Driver junta tudo para você ver o resultado final.

3. O que é um RDD?
Resilient Distributed Dataset — a lista mágica do Spark
📋
Analogia: Lista de Chamada dividida
Imagine que você tem uma lista com 1 milhão de nomes. Um professor sozinho levaria horas para fazer a chamada. Mas se você dividir em pedaços e dar para 1.000 professores diferentes, cada um faz uma parte — e fica pronto em minutos.

O RDD é essa lista dividida entre vários computadores. Cada computador (Executor) guarda e processa apenas um pedaço dela.

⚙️ O que você pode fazer com um RDD?

Existem dois tipos de operações: Transformações (preparam os dados, mas não executam nada ainda) e Ações (disparam a execução e mostram o resultado).

map()
⚙️ Transformação
Aplica uma função a cada elemento da lista.
# Dobrar cada número
.map(lambda x: x * 2)
filter()
⚙️ Transformação
Filtra apenas os elementos que atendem a uma condição.
# Só linhas com ERROR
.filter(lambda l: "ERROR" in l)
flatMap()
⚙️ Transformação
Como map(), mas achata listas dentro de listas.
# Separar palavras de frases
.flatMap(lambda l: l.split(" "))
count()
▶️ Ação
Conta o número total de elementos.
# Contar linhas de erro
erros.count() → 42
collect()
▶️ Ação
Traz todos os dados para o Driver (cuidado: pode ser grande!).
# Pegar tudo
rdd.collect() → [1, 2, 3...]
reduce()
▶️ Ação
Combina todos os elementos em um único resultado.
# Somar todos
.reduce(lambda a,b: a+b)
// PERGUNTA 2 DE 3
🧠 Você quer pegar os logs de erro e contar quantos existem. Qual sequência está certa?
🎉 +50 XP! Certo! filter() filtra os dados (transformação), depois count() conta o resultado (ação). Sempre: transformar → agir!
❌ Pense assim: você primeiro seleciona o que quer (filter = transformação), e só depois conta (count = ação). Transformação sempre vem antes da ação!
💡 Precisa de uma dica?
Pense no seu dia a dia: você primeiro filtra o café (separa o pó da água) e só depois bebe. Primeiro transforma, depois age!

4. Lazy Evaluation — O Spark é "preguiçoso"!
Ele só trabalha quando você pede com uma Ação
📝
Analogia: A lista de tarefas
Imagine que você pede para um funcionário: "Separe os erros dos logs" → ele anota. "Extraia as mensagens" → ele anota. "Remova duplicatas" → ele anota.

Ele só começa a trabalhar de verdade quando você diz: "Me dê o resultado!" (count, collect...). Antes disso, ele só fica anotando em um caderninho (o DAG). Isso é Lazy Evaluation!

Veja como o Spark constrói e executa o pipeline:

😴 anota

😴 anota

😴
Transformações = Lazy
map(), filter(), flatMap()... só anotam no plano. Nada acontece ainda!
🚀
Ações = Disparam tudo!
count(), collect(), reduce()... aí o Spark executa tudo de uma vez!
⚡
Por que isso é bom?
O Spark pode otimizar o plano antes de executar, tornando-o mais eficiente!

🧠 Você escreveu este código:
rdd2 = rdd.filter(lambda x: x > 0).map(lambda x: x * 2)

Quando o Spark processa os dados de verdade?
🎉 +50 XP! Perfeito! O Spark é "preguiçoso" — filter() e map() só anotam no plano. Ele só trabalha de verdade quando você pede com uma ação!
❌ Lembre da analogia: o funcionário anota tudo sem fazer nada. Ele só age quando você diz "me dê o resultado!" (count, collect...).
💡 Precisa de uma dica?
Lembra da analogia? filter() e map() são "anotações no caderninho". O Spark só processa quando você chama uma Ação!

📓 Célula 2 — Seu primeiro RDD no Colab! 
from pyspark import SparkContext

# Inicia o Spark (local = usa sua máquina/Colab)
sc = SparkContext("local[*]", "MeuPrimeiroRDD")

# Cria um RDD com números
numeros = sc.parallelize([1, 2, 3, 4, 5])

# Transforma (multiplica por 2) e soma tudo
resultado = numeros.map(lambda x: x * 2).reduce(lambda a, b: a + b)
print(f"Resultado: {resultado}")  # Esperado: 30
