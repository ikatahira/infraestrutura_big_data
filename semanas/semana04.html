⚡Por que Spark? Spark vs MapReduce

MapReduce funciona, mas tem um problema: a cada passo ele grava os dados no disco HDFS. Isso é lento. Spark mantém os dados na memória entre os passos — muito mais eficiente para tarefas iterativas.

🐢 MapReduce
💾 Salva no disco a cada operação
🐌 Lento para algoritmos iterativos
☕ API verbosa em Java
✅ Ótimo para batch único grande
🚀 Apache Spark
🧠 Processa na memória RAM
⚡ Até 100x mais rápido em ML
🐍 APIs em Python, Scala, Java, R
✅ Batch + Streaming + ML + SQL
🧠 Quiz 1 — Por que o Spark é mais rápido que o MapReduce para algoritmos de Machine Learning iterativos?
✅ Correto! +60 XP. Em ML, o mesmo dataset é lido dezenas de vezes. MapReduce leria do disco a cada iteração; Spark mantém na RAM.
❌ A chave está no armazenamento em memória (RAM) vs disco. Dados na RAM são ~1000x mais rápidos de acessar.
🏗️Arquitetura Spark — Driver + Executors

O Spark tem uma arquitetura mestre-escravo. O Driver coordena tudo, os Executors fazem o trabalho pesado nos nós do cluster.

🧠
DRIVER
SparkContext. Coordena o job, cria o DAG, distribui tarefas
🎯
CLUSTER MANAGER
YARN / Standalone / Kubernetes. Gerencia recursos
⚙️
EXECUTOR
Roda em cada nó worker. Executa tasks, armazena em cache
🔵RDDs — Resilient Distributed Datasets

RDD é a abstração central do Spark: uma coleção de dados distribuída, imutável e tolerante a falhas. Pense nele como uma "lista distribuída" entre os nós.

Transformações (lazy) criam um novo RDD mas não executam nada ainda. Ações disparam a execução real.

OperaçãoTipoO que fazExemplo
map()TransformaçãoAplica função a cada elemento.map(x => x*2)
filter()TransformaçãoFiltra elementos por condição.filter(x => x > 0)
flatMap()Transformaçãomap + achata resultados.flatMap(linha => linha.split(" "))
collect()AçãoTraz todos os dados ao Driver.collect()
count()AçãoConta o número de elementos.count()
reduce()AçãoAgrega com uma função.reduce(lambda a,b: a+b)
🧠 Quiz 2 — Você quer filtrar linhas de um RDD com erros e contar quantas são. Qual sequência de operações está correta?
✅ Correto! +70 XP. filter() é transformação (lazy), count() é ação (dispara execução). Sempre: transformações primeiro, ação no final.
❌ Lembre: você aplica transformações (filter, map) para definir o pipeline, depois dispara com uma ação (count, collect).
rdd_exemplo.py — PySpark
from pyspark import SparkContext sc = SparkContext("local", "MeuApp") # Criar RDD a partir de arquivo no HDFS logs = sc.textFile("hdfs:///logs/app.log") # Pipeline: transformações (lazy) + ação erros = (logs .filter(lambda linha: "ERROR" in linha) # transf. .map(lambda linha: linha.split(" ")[2]) # transf. .distinct() # transf. ) # Apenas aqui o Spark EXECUTA tudo ↓ print(f"Tipos únicos de erro: {erros.count()}") # ação! print(erros.collect()) # ação!
😴Lazy Evaluation — O segredo da eficiência do Spark

Spark NÃO executa nada quando você chama map() ou filter(). Ele apenas registra o que precisa ser feito (o DAG). Só quando você chama uma ação é que o Spark otimiza e executa tudo de uma vez.

🧠 Quiz 3 — Você escreveu: rdd2 = rdd.filter(x > 0).map(x * 2). Quando o Spark realmente processa os dados?
✅ Lazy Evaluation! +60 XP. O Spark apenas anota as transformações no DAG. Nenhum dado é movido até uma ação ser chamada — isso permite otimizações internas.
❌ Lazy Evaluation: filter() e map() apenas constroem o plano. A execução real só acontece com uma ação (count, collect, saveAsTextFile...).
