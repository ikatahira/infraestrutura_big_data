🗄️Os 4 Tipos de Bancos NoSQL

NoSQL não é um banco de dados — é uma família de abordagens. Cada tipo resolve um problema diferente. Conhecer todos é essencial para escolher a ferramenta certa.

🗝️
Chave-Valor
Redis, DynamoDB, Riak
Dados simples com acesso ultra-rápido por chave. Cache, sessões, filas.
📄
Documentos
MongoDB, CouchDB, Firestore
Documentos JSON flexíveis. Dados semiestruturados, schemas variáveis.
📊
Colunar
Cassandra, HBase, Bigtable
Leitura/escrita massiva por colunas. IoT, logs, séries temporais.
🔗
Grafos
Neo4j, Amazon Neptune, JanusGraph
Relacionamentos complexos. Redes sociais, rotas, detecção de fraude.
🧠 Quiz 1 — Uma rede social precisa encontrar "amigos de amigos" eficientemente. Qual tipo de banco NoSQL é mais adequado?
✅ +50 XP! Grafos modelam relacionamentos diretamente. Encontrar "amigos de amigos" em SQL exige JOINs caros; em grafos é uma travessia simples.
❌ Pense em "relacionamentos". Quando a query principal é sobre como os dados se conectam, banco de grafos é a resposta.

⚖️Teorema CAP — A Lei dos Trade-offs do Big Data

O Teorema CAP afirma: um sistema distribuído só pode garantir 2 das 3 propriedades ao mesmo tempo. Escolher um banco é escolher qual propriedade sacrificar.

C — Consistency (Consistência)
Todos os nós veem os mesmos dados ao mesmo tempo. Leitura sempre retorna a versão mais recente.
A — Availability (Disponibilidade)
Todo request recebe uma resposta — mesmo que não seja a mais atual. Sistema nunca fica offline.
P — Partition Tolerance (Tolerância a Partição)
Sistema continua funcionando mesmo se a rede entre nós falhar. Essencial em sistemas distribuídos reais.
Onde cada banco se encaixa:
🍃
MongoDB, CouchDB
AP — Disponível + Tolerante a Partição
💫
Cassandra, DynamoDB
AP — Disponível + Tolerante a Partição
🐘
HBase, BigTable
CP — Consistente + Tolerante a Partição
🗄️
MySQL, PostgreSQL (tradicional)
CA — Consistente + Disponível (não distribuído)
🧠 Quiz 2 — Um banco de dados financeiro (transferências bancárias) precisa garantir que todos os nós sempre vejam o saldo correto. Qual combinação CAP escolher?
✅ +60 XP! Para dados financeiros, CP é a escolha certa. É melhor o sistema ficar indisponível por um instante do que ter saldos inconsistentes — o que poderia permitir transferências inválidas.
❌ Pense: o que é pior — site fora por 1 segundo, ou mostrar saldo errado e permitir fraude? Para dados financeiros, CP (Consistency + Partition Tolerance) é obrigatório.
🎮Jogo: Qual banco NoSQL escolher? — 5 Cenários

Para cada cenário abaixo, escolha o banco NoSQL mais adequado. Acertar todos desbloqueia o badge Cenário Solver!

📱 Cenário 1: Um app de e-commerce precisa de cache ultra-rápido para sessões de usuário (carrinho, login). Qual banco?
⚡ Redis
🍃 MongoDB
💫 Cassandra
🔗 Neo4j
✅ Redis! Cache chave-valor in-memory. Sub-milissegundo de latência. Perfeito para sessões e carrinho.
❌ Para cache rápido de sessões, Redis (chave-valor in-memory) é a escolha padrão da indústria.
📰 Cenário 2: Um CMS de blog com artigos que têm campos variáveis (alguns têm vídeo, outros apenas texto, tags diferentes). Qual banco?
🍃 MongoDB
⚡ Redis
🐘 HBase
🔗 Neo4j
✅ MongoDB! Documentos JSON flexíveis — cada artigo pode ter campos diferentes sem alterar o schema.
❌ Dados com estrutura variável (campos opcionais) → MongoDB (documentos). Schema flexível é sua característica principal.
📊 Cenário 3: Uma plataforma de IoT recebe 500 mil leituras de sensores por segundo, 24/7, armazenadas por data/hora. Qual banco?
💫 Cassandra
🍃 MongoDB
🔗 Neo4j
⚡ Redis
✅ Cassandra! Colunar distribuído, escrita massiva, sem ponto único de falha. Projetado exatamente para séries temporais e IoT.
❌ Alta taxa de escrita + séries temporais = Cassandra. Foi criado para suportar escritas massivas distribuídas (usado pela Netflix, Instagram).
🕵️ Cenário 4: Sistema antifraude de banco precisa detectar padrões suspeitos analisando a REDE de transações entre contas. Qual banco?
🔗 Neo4j
💫 Cassandra
🍃 MongoDB
⚡ Redis
✅ Neo4j! Grafos são perfeitos para análise de redes. "Esta conta transferiu para conta que transferiu para conta suspeita em 3 saltos" é uma query natural em grafos.
❌ Quando o problema é sobre RELAÇÕES e REDES → banco de grafos (Neo4j). Detecção de fraude analisa padrões de conexões, não apenas dados isolados.
☁️ Cenário 5: Uma startup precisa de um banco totalmente gerenciado na AWS, serverless, que escale automaticamente para uma aplicação móvel global. Qual banco?
🌩️ DynamoDB (AWS)
🍃 MongoDB on-premise
🐘 HBase no Hadoop
🔗 Neo4j
✅ DynamoDB! Gerenciado pela AWS, serverless, escala automática, pague pelo uso. Para startups sem equipe de infra é a escolha ideal.
❌ "Serverless + AWS + escala automática" = DynamoDB. É o banco NoSQL mais popular da nuvem por ser totalmente gerenciado.
⚗️ACID vs BASE — Dois Modelos de Consistência

SQL segue ACID. NoSQL geralmente segue BASE — um modelo mais relaxado que permite maior escalabilidade.

🔒 ACID (SQL Tradicional)
Atomicity — tudo ou nada: transação completa ou reverte
Consistency — dados sempre em estado válido
Isolation — transações não interferem entre si
Durability — dado salvo persiste mesmo em falhas
🌊 BASE (NoSQL)
BAsically Available — sistema responde sempre
Soft state — dados podem estar em transição
Eventually consistent — todos os nós convergem no tempo
