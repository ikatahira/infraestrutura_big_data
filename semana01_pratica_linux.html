1

Acessando o Ambiente (Nível Zero)

☁️ Configuração inicial ▼
1️⃣ Acesse o Google Cloud Shell
Abra 🔗 shell.cloud.google.com e faça login com sua conta Google. Ao abrir, você verá um terminal Linux pronto para uso.
2️⃣ Verificar o ambiente
Digite os comandos abaixo para identificar o sistema operacional e o diretório atual:
$uname -a
# Mostra o sistema operacional e arquitetura
$pwd
# Mostra seu diretório atual
📌 Conexão com Big Data Todos os clusters Hadoop e Spark rodam sobre sistemas Linux semelhantes a esse. O terminal que você acabou de acessar é o mesmo tipo de interface usada por engenheiros de dados ao administrar clusters de produção.
2

Organização de Armazenamento (Data Lake Simulado)

🗄️ Estrutura HDFS ▼

🎯 Objetivo desta parte

  • Simular a estrutura de diretórios de um Data Lake com dados brutos e processados.
📁 Crie a estrutura de diretórios
$mkdir -p bigdata/raw
$mkdir -p bigdata/processed
$mkdir -p bigdata/logs
$ls -R bigdata
# Verifique a estrutura criada
📄 Crie um dataset fictício
$echo "id,nome,valor" > bigdata/raw/dados.csv
$echo "1,produtoA,100" >> bigdata/raw/dados.csv
$cat bigdata/raw/dados.csv
# Visualize o conteúdo gerado
📌 Relação com Big Data raw → dados brutos (Data Lake)  |  processed → dados tratados  |  logs → monitoramento do sistema.
Essa é exatamente a lógica usada em ambientes Hadoop com HDFS.
3

Processamento Simulado

🔁 Pipeline MapReduce ▼
🔄 Simule uma transformação de dados via pipeline
$cat bigdata/raw/dados.csv | grep produtoA > bigdata/processed/dados_filtrados.csv
$cat bigdata/processed/dados_filtrados.csv
📌 Conexão com MapReduce O pipeline com | (pipe) simula o fluxo: Entrada → Processamento → Saída. É o mesmo conceito estrutural do processamento distribuído — cada etapa é análoga a uma fase Map ou Reduce no Hadoop.
4

Monitoramento de Recursos

📊 CPU / Memória ▼
📊 Verificar uso do sistema
$top
# Observe CPU, Memória e Processos — pressione Q para sair
💡 Observe os campos: %CPU, %MEM e a coluna PID — você vai precisar do PID a seguir.
💥 Simule carga de CPU
$yes > /dev/null &
# Observe o aumento da CPU no top
$top
# Anote o PID do processo 'yes' e finalize-o:
$kill <PID>
📌 Relação com Infraestrutura Em clusters reais, monitorar consumo é essencial para evitar gargalos, garantir desempenho e escalar horizontalmente. Ferramentas como YARN ResourceManager e Spark UI fazem isso automaticamente em produção.

5

Introdução a Containers (Simulando Nós de Cluster)

🐳 Docker ▼
🐳 Verifique o Docker e crie a rede do cluster
$docker --version
$docker network create cluster-net
🖧 Crie os containers master e worker
$docker run -dit --name master --network cluster-net ubuntu
$docker run -dit --name worker --network cluster-net ubuntu
$docker ps
# Liste os containers em execução
📌 Relação com Big Data Cada container representa um nó do cluster. Em Hadoop real, o master executa o NameNode e o ResourceManager; os workers executam DataNodes e NodeManagers.
6

Comunicação Entre Nós

📡 Rede de cluster ▼
📡 Entre no master e instale o ping
$docker exec -it master bash
# Dentro do container master:
#apt update && apt install -y iputils-ping
#ping worker
# Teste a comunicação com o nó worker
#exit
📌 Infraestrutura real Clusters Hadoop dependem da comunicação constante entre nós via TCP/IP. O NameNode precisa se comunicar com todos os DataNodes para coordenar a replicação de blocos de dados.
💡 Dica: Se o ping travar, use Ctrl+C para interrompê-lo. Use exit para sair do container.
7

Automação com Shell Script

⚙️ DevOps / IaC ▼
📝 Crie o script de inicialização
$nano init_cluster.sh
Insira o seguinte conteúdo no editor nano:
#!/bin/bash
echo "Inicializando estrutura Big Data"
mkdir -p bigdata/raw
mkdir -p bigdata/processed
echo "Cluster pronto"
💡 Para salvar no nano: Ctrl+O → Enter → Ctrl+X
⚙️ Permita execução e execute o script
$chmod +x init_cluster.sh
$./init_cluster.sh
📌 Relação com infraestrutura moderna Automação é a base de DevOps e Infraestrutura como Código (IaC). Ferramentas como Ansible, Terraform e scripts Bash são usados para provisionar clusters inteiros de forma repetível e escalável.
