🐧 Processos, Memória RAM e Swap
Toda ferramenta de Big Data que você vai instalar (Hadoop, Spark) roda como processos Linux consumindo RAM. Entender isso evita muita dor de cabeça de VM travando.

Processo (PID) — cada programa em execução no Linux tem um número único de identificação. Você já viu isso na Semana 01 com ps aux. Um serviço Hadoop, por exemplo, roda como vários processos (NameNode, DataNode) simultaneamente.

RAM (memória de trabalho) — onde tudo que está sendo processado agora fica temporariamente. Quando você inicia o Hadoop, ele reserva uma parte da RAM só para ele.

Swap — quando a RAM enche, o Linux usa uma parte do disco como "memória de emergência". É muito mais lento que RAM. Se seu Hadoop/Spark começa a usar swap pesadamente, é sinal de que a VM precisa de mais RAM.

htop / free -h — ferramentas de diagnóstico que você já viu de relance na Semana 01. Agora, preste atenção: RAM livre baixa + swap sendo usado = hora de fechar processos ou aumentar a RAM da VM.

🔐 Permissões, Usuários e Automação com Shell Script
Permissões de arquivo — todo arquivo Linux tem 3 tipos de permissão (leitura, escrita, execução) para 3 categorias (dono, grupo, outros). O Hadoop, por exemplo, precisa rodar sob um usuário com permissão de leitura/escrita nas pastas de dados.

chmod — muda as permissões de um arquivo. Ex: chmod 755 script.sh dá permissão total ao dono, e leitura+execução para os demais.

chown — muda o dono de um arquivo. Útil quando você precisa que o usuário hadoop (criado na Semana 02... ou melhor, que vamos criar na Semana 05) seja dono das pastas de dados.

Shell script — um arquivo .sh com uma sequência de comandos Linux, executado de uma vez só. Em vez de digitar 10 comandos toda vez que quiser iniciar o Hadoop, você escreve um script uma vez e roda com ./iniciar.sh.

🛠️ Prática — Diagnóstico de Sistema e Primeiro Shell Script
⚡ +200 XP ⏱ ~25 min Prática 📋 Ementa: Desempenho e segurança de sistemas operacionais para Big Data
🔒
▾
Vamos fechar o mês de nivelamento colocando tudo em prática: diagnóstico de sistema, permissões e seu primeiro script de automação.
01
Diagnosticar processos e memória da sua VM
Vamos ver o que está consumindo RAM agora mesmo:
bash
htop # pressione F6 para ordenar por uso de memória, q para sair free -h ps aux --sort=-%mem | head -10
02
Criar um arquivo e testar permissões
Vamos criar um script simples e ajustar suas permissões:
bash
echo '#!/bin/bash\necho "Verificando sistema..."\nfree -h\ndf -h /\nnproc' > verificar.sh ls -l verificar.sh # repare que ainda não tem permissão de execução (sem x)
03
Dar permissão de execução e rodar o script
Use chmod para liberar a execução:
bash
chmod +x verificar.sh ls -l verificar.sh # agora aparece x nas permissões ./verificar.sh
ℹ️ Você acabou de automatizar os mesmos comandos que rodou manualmente na Semana 01 (Missão de Hardware) — isso é exatamente o tipo de script que vamos usar para automatizar o início do Hadoop nas próximas semanas.
04
Testar mudança de dono com chown (opcional, requer sudo)
Se quiser ver o chown em ação:
bash
whoami # veja quem é o dono atual do arquivo ls -l verificar.sh
