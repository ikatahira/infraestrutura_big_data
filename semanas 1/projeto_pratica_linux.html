Acessando o Ambiente (Nível Zero)

☁️ Configuração inicial ▼
🖥️ O que é o Google Cloud Shell? O Google Cloud Shell é um terminal Linux hospedado na nuvem do Google, acessível pelo navegador sem instalar nada. Por baixo há uma VM Debian com 5 GB de disco persistente e ferramentas de desenvolvimento já instaladas — incluindo o Docker. É o tipo de ambiente que engenheiros de dados usam para gerenciar clusters remotos em produção.
1️⃣ Acesse o Google Cloud Shell
Abra 🔗 shell.cloud.google.com e faça login com sua conta Google. Ao abrir, você verá um terminal Linux pronto para uso.
2️⃣ Verificar o ambiente
Digite os comandos abaixo para identificar o sistema operacional e o diretório atual:
$uname -a
# Mostra o sistema operacional e arquitetura
$pwd
# Mostra seu diretório atual
📌 Conexão com Big DataTodos os clusters Hadoop e Spark rodam sobre sistemas Linux. O terminal que você acessou é o mesmo tipo de interface usado por engenheiros ao administrar clusters de produção.
2

Organização de Armazenamento (Data Lake Simulado)

🗄️ Estrutura HDFS ▼
📁 Sistema de arquivos Linux No Linux tudo é arquivo ou diretório. O comando mkdir -p cria um diretório e todos os seus "pais" automaticamente. ls -R lista recursivamente. Essa estrutura espelha a lógica do HDFS, onde dados brutos (raw), processados e de log ficam em caminhos separados — formando um Data Lake.
📁 Crie a estrutura de diretórios
$mkdir -p bigdata/raw
$mkdir -p bigdata/processed
$mkdir -p bigdata/logs
$ls -R bigdata
# Verifique a estrutura criada
📄 Crie um dataset fictício
$echo "id,nome,valor" > bigdata/raw/dados.csv
$echo "1,produtoA,100" >> bigdata/raw/dados.csv
$cat bigdata/raw/dados.csv
📌 Relação com Big Dataraw dados brutos | processed dados tratados | logs monitoramento. Essa é a lógica usada em ambientes Hadoop com HDFS e em Data Lakes modernos como S3 e Azure Data Lake.
3

Processamento Simulado

🔁 Pipeline MapReduce ▼
🔧 O que é o pipe | ? O pipe (|) conecta a saída de um comando à entrada do próximo, formando um pipeline. É o conceito fundamental de composição no Linux e aparece diretamente no MapReduce: dados passam por etapas sequenciais de transformação (Map → Shuffle → Reduce), exatamente como nos pipes do shell.
🔄 Simule uma transformação de dados via pipeline
$cat bigdata/raw/dados.csv | grep produtoA > bigdata/processed/dados_filtrados.csv
$cat bigdata/processed/dados_filtrados.csv
📌 Conexão com MapReducePipeline com |: Entrada → Processamento → Saída. É o mesmo conceito estrutural do processamento distribuído — cada etapa é análoga a uma fase Map ou Reduce no Hadoop.
⚙️ Prática: Simulação de MapReduce
Utilizaremos o pipe (|) para encadear comandos, simulando o fluxo Map -> Shuffle -> Reduce descrito no vídeo:
$cat bigdata/raw/dados.csv | grep "produtoA" | wc -l
# cat (Map) | grep (Shuffle) | wc (Reduce)
📌 Conexão com Big Data O que você fez acima é uma "Pipeline de Dados". No Apache Spark ou Hadoop, a lógica é a mesma, mas distribuída entre milhares de máquinas.
4

Monitoramento de Recursos

📊 CPU / Memória ▼
📊 Comandos de monitoramento Linux top é um monitor de processos em tempo real — mostra CPU, memória e lista os processos por consumo. Cada linha representa um processo com seu PID (Process ID), um número único de identificação. Com kill <PID> você termina qualquer processo. Em clusters Spark/Hadoop reais, o YARN ResourceManager e o Spark UI fazem esse monitoramento de forma distribuída e visual.
📊 Verificar uso do sistema
$top
# Pressione Q para sair
💡 Observe: %CPU, %MEM e a coluna PID — você vai precisar do PID a seguir.
💥 Simule carga de CPU
$yes > /dev/null &
# O & envia o processo para background
$top
# Anote o PID do processo 'yes' e finalize:
$kill <PID>
📌 Relação com InfraestruturaEm clusters reais, monitorar consumo é essencial para evitar gargalos e escalar horizontalmente. Ferramentas como YARN ResourceManager e Spark UI fazem isso automaticamente em produção.

Introdução a Containers (Simulando Nós de Cluster)

🐳 Docker ▼
🐳 O que é Docker e o que é um Container? Imagine uma máquina virtual ultra-leve. Um container Docker é um processo isolado com seu próprio sistema de arquivos, bibliotecas e configurações — mas sem precisar de um SO completo, pois compartilha o kernel do host. O Docker é o motor que cria, executa e gerencia esses containers.

Analogia para Ciência de Dados: se uma VM é uma casa inteira, um container é um apartamento — compartilha a estrutura do prédio (kernel), mas tem seu próprio espaço isolado, muito mais rápido para criar e destruir.
🐳 Verifique o Docker e crie a rede do cluster
$docker --version
$docker network create cluster-net
💡 docker network create cria uma rede virtual privada. Containers nela se comunicam pelo nome, como se fossem máquinas numa LAN corporativa.
🖧 Crie os containers master e worker
$docker run -dit --name master --network cluster-net ubuntu
$docker run -dit --name worker --network cluster-net ubuntu
$docker ps
💡 -d = background  |  -i = interativo  |  -t = pseudo-terminal
📌 Relação com Big DataCada container representa um nó do cluster. Em Hadoop real, o master executa NameNode e ResourceManager; os workers executam DataNodes e NodeManagers.
6

Comunicação Entre Nós

📡 Rede de cluster ▼
📡 Como containers se comunicam? Quando containers estão na mesma rede Docker, o Docker funciona como um DNS interno: resolve automaticamente o nome do container para o IP correspondente. Ao digitar ping worker dentro do container master, o Docker traduz "worker" para o IP correto. Em clusters Hadoop reais, o NameNode precisa se comunicar constantemente com os DataNodes via TCP/IP para coordenar replicação de blocos de dados.
📡 Entre no master e instale o ping
$docker exec -it master bash
# Dentro do container master:
#apt update && apt install -y iputils-ping
#ping worker
# Teste a comunicação com o nó worker
#exit
💡 Se o ping travar, use Ctrl+C para interrompê-lo. Use exit para sair do container.
7

Automação com Shell Script

⚙️ DevOps / IaC ▼
⚙️ O que é Shell Script? E o editor Nano? Um Shell Script é um arquivo de texto com uma sequência de comandos Linux que o Shell (interpretador, como o bash) executa automaticamente. É a forma mais simples de automação no Linux.

O Nano é um editor de texto que roda no terminal sem interface gráfica. É minimalista: você escreve e usa atalhos. A linha #!/bin/bash no início — chamada shebang — informa ao sistema qual interpretador deve executar o arquivo.
📝 Crie o script de inicialização
$nano init_cluster.sh
Se o nano não estiver instalado: apt-get update && apt-get install nano -y
Insira o conteúdo abaixo:
#!/bin/bash
echo "Inicializando estrutura Big Data"
mkdir -p bigdata/raw
mkdir -p bigdata/processed
echo "Cluster pronto"
💡 Salvar no nano: Ctrl+O → Enter  |  Sair: Ctrl+X
⚙️ Permita execução e execute o script
$chmod +x init_cluster.sh
# chmod +x dá permissão de execução ao arquivo
$./init_cluster.sh
# ./ significa "execute no diretório atual"
📌 Relação com infraestrutura modernaAutomação é a base de DevOps e IaC. Ferramentas como Ansible, Terraform e scripts Bash provisionam clusters inteiros de forma repetível e escalável.

Pipe ( | )
O pipe | encadeia comandos: a saída (stdout) da esquerda vira a entrada (stdin) da direita. Permite pipelines de processamento sem arquivos intermediários, tornando o código elegante e eficiente.
cat dados.csv | grep "A" | wc -l

🐧 Linux
chmod
chmod controla quem pode ler (r), escrever (w) ou executar (x) um arquivo. chmod +x adiciona execução para todos. chmod 755 usa notação octal: dono tem tudo, outros leem e executam.
chmod +x script.sh
chmod 755 script.sh
🐘 Em clusters, permissões controlam quais serviços acessam dados sensíveis no HDFS. Segurança é crítica em ambientes multi-tenant.

🐧 Linux
PID (Process ID)
Todo processo no Linux recebe um PID — número inteiro único. O top mostra os PIDs de todos os processos ativos. Com kill <PID> você encerra um processo; kill -9 <PID> força a finalização imediata.
top # veja PIDs
kill 1234 # encerra 1234
kill -9 1234 # força
🐘 Admins usam PIDs para reiniciar processos do NameNode ou DataNode travados. Em Kubernetes, o equivalente são os "Pods".

Data Lake
Um Data Lake armazena dados em formato bruto sem estrutura prévia: estruturados (CSV, SQL), semiestruturados (JSON) e não-estruturados (imagens, logs). A estrutura raw/ → processed/ → logs/ que criamos simula essa arquitetura.

🐘 HDFS, Amazon S3, Azure Data Lake e Google Cloud Storage são implementações reais de Data Lakes usadas em produção.

MapReduce

👆 Clique para saber mais
🐘 Big Data
MapReduce
Paradigma com duas fases: Map (transforma/filtra dados em paralelo em vários nós) e Reduce (agrega os resultados parciais). O pipe Linux simula essa lógica sequencial, porém de forma distribuída o Hadoop executa em centenas de nós simultaneamente.
cat dados.csv | grep "A" # Map
| wc -l # Reduce
🐘 Hadoop MapReduce opera em disco; Spark faz o equivalente em memória RAM, sendo até 100x mais rápido para iterações.

🐘 Big Data
Cluster Master/Worker
Um cluster é um grupo de nós interconectados. O master coordena (agenda tarefas, gerencia metadados) e os workers executam o processamento. Nesta aula simulamos com 2 containers; clusters de produção têm centenas de nós.
master → NameNode + ResourceManager
worker → DataNode + NodeManager
🐘 Um cluster Hadoop de produção pode ter 1000+ nós processando petabytes. Empresas como Facebook e LinkedIn operaram clusters desse porte.
