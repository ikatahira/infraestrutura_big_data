⚖️RDD vs DataFrame — Quando usar cada um?
🔵 RDD
🔧 Dados sem estrutura definida
🐍 Lógica complexa em Python/Scala
⚙️ Controle total do pipeline
❌ Sem otimização automática
📋 DataFrame
📐 Dados tabulares com schema
🚀 Otimizado pelo Catalyst
🔤 Suporta SQL nativo
✅ Recomendado para a maioria dos casos
🧠 Quiz 1 — Você tem dados de vendas em CSV com colunas definidas (produto, valor, data). O que é mais adequado?
✅ +60 XP! DataFrames são a escolha certa para dados estruturados. O Catalyst Optimizer gera um plano de execução muito mais eficiente do que RDDs puros.
❌ Dados com schema definido → DataFrame. O Spark consegue otimizar muito melhor quando sabe a estrutura dos dados.
📋Como criar e operar DataFrames em PySpark

Um DataFrame é como uma tabela de banco de dados distribuída. Tem colunas com tipos definidos e suporta operações estilo SQL.

DataFrame: employees.csv → Spark

dataframe_ops.py
from pyspark.sql import SparkSession from pyspark.sql.functions import col, avg, count, desc spark = SparkSession.builder.appName("Analise").getOrCreate() # Ler CSV com detecção automática de schema df = spark.read.csv("employees.csv", header=True, inferSchema=True) df.printSchema() # mostra tipos de cada coluna df.show(5) # mostra 5 primeiras linhas # SELECT: escolher colunas df.select("nome", "salario").show() # FILTER: filtrar linhas df.filter(col("salario") > 9000).show() # GROUPBY + AGG: média salarial por depto df.groupBy("departamento") \ .agg(avg("salario").alias("media_salario"), count("*").alias("total_func")) \ .orderBy(desc("media_salario")) \ .show()
🧠 Quiz 2 — Você quer selecionar apenas funcionários ativos E com salário acima de 9000. Como fazer?
✅ +70 XP! Use col() para referenciar colunas e & para combinar condições. Parênteses são obrigatórios em cada condição para precedência correta.
❌ A forma correta usa col() para cada coluna e & para combinar: df.filter((col("ativo") == True) & (col("salario") > 9000))
🔤Spark SQL — SQL Padrão em Dados Distribuídos

O Spark permite registrar um DataFrame como "tabela temporária" e depois escrever SQL padrão sobre ele. Isso é especialmente útil para equipes que já conhecem SQL.

spark_sql.py
# Registrar DataFrame como tabela temporária df.createOrReplaceTempView("funcionarios") # Agora pode escrever SQL padrão! resultado = spark.sql(""" SELECT departamento, COUNT(*) AS total, AVG(salario) AS media_sal, MAX(salario) AS maior_sal FROM funcionarios WHERE ativo = true GROUP BY departamento ORDER BY media_sal DESC """) resultado.show()
📊 Resultado da Query SQL
departamento total media_sal maior_sal ───────────── ───── ────────── ────────── Dados 2 10100.0 11000.0 Engenharia 1 8500.0 8500.0
🧠 Quiz 3 — Para executar SQL no Spark, qual passo é necessário ANTES de chamar spark.sql()?
✅ +60 XP! SQL Wizard desbloqueado! O createOrReplaceTempView("nome") cria uma visão temporária que o Spark SQL pode consultar como se fosse uma tabela SQL.
❌ Antes do spark.sql(), você precisa registrar o DataFrame: df.createOrReplaceTempView("nome_tabela"). Sem isso, o SQL não sabe de onde ler os dados.
💾Formatos de Dados — CSV, JSON, Parquet
📄
CSV
Simples, legível por humanos. Sem schema. Lento para leitura em Big Data.
{ }
JSON
Flexível, semiestruturado. Ótimo para dados aninhados. Maior tamanho.
🗜️
Parquet
Colunar, comprimido. Muito eficiente para Spark e Big Data. Recomendado!
🔷
ORC
Similar ao Parquet. Popular no ecossistema Hive/Hadoop.

# Ler diferentes formatos df_csv = spark.read.csv("data.csv", header=True) df_json = spark.read.json("data.json") df_parq = spark.read.parquet("data.parquet") # Salvar em Parquet (recomendado para Big Data!) df.write.parquet("output/", mode="overwrite") # Particionar por coluna (melhora queries futuras) df.write.partitionBy("departamento").parquet("output_part/")
