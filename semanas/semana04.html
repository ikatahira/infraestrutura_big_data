⚡Por que Spark? Spark vs MapReduce

MapReduce funciona, mas tem um problema crítico: a cada passo ele grava os dados no disco HDFS. Isso é lento. O Spark mantém os dados na memória entre os passos — muito mais eficiente para tarefas iterativas como Machine Learning.

🐢 MapReduce
💾 Salva no disco a cada operação
🐌 Lento para algoritmos iterativos
☕ API verbosa em Java
✅ Ótimo para batch único grande
🚀 Apache Spark
🧠 Processa na memória RAM
⚡ Até 100x mais rápido em ML
🐍 APIs em Python, Scala, Java, R
✅ Batch + Streaming + ML + SQL
// QUIZ 01
🧠 Por que o Spark é mais rápido que o MapReduce para algoritmos de Machine Learning iterativos?
✅ Correto! +50 XP. Em ML, o mesmo dataset é lido dezenas de vezes. MapReduce leria do disco a cada iteração; Spark mantém na RAM, que é ~1.000x mais rápida.
❌ A chave está no armazenamento em memória (RAM) vs disco. Dados na RAM são ~1.000x mais rápidos de acessar. Tente novamente na próxima sessão!
💡 Dica
Pense em ML: você treina um modelo por 100 épocas. Quantas vezes o dataset é lido? Onde Spark guarda isso entre as iterações?
🏗️Arquitetura Spark — Driver + Executors

O Spark tem arquitetura mestre-escravo. O Driver coordena tudo, os Executors fazem o trabalho pesado nos nós do cluster.

🧠
DRIVER
SparkContext. Coordena o job, cria o DAG e distribui as tasks
🎯
CLUSTER MANAGER
YARN / Standalone / Kubernetes. Gerencia os recursos físicos
⚙️
EXECUTOR
Roda em cada nó worker. Executa tasks e armazena dados em cache

Fluxo: Seu código PySpark roda no Driver → Driver cria o plano de execução (DAG) → Cluster Manager aloca Executors → Executors processam partições dos dados em paralelo → resultado volta ao Driver.

🔵RDDs — Resilient Distributed Datasets

RDD é a abstração central do Spark: uma coleção de dados distribuída, imutável e tolerante a falhas. Pense nele como uma "lista gigante" particionada entre os nós do cluster.

Transformações (lazy) criam um novo RDD mas não executam nada ainda. Ações disparam a execução real do pipeline.

rdd_pipeline.py — PySpark
from pyspark import SparkContext sc = SparkContext("local", "MeuApp") # Criar RDD a partir de arquivo no HDFS logs = sc.textFile("hdfs:///logs/app.log") # Transformações (lazy) — só anotam no DAG erros = (logs .filter(lambda linha: "ERROR" in linha) # transf. .map(lambda linha: linha.split(" ")[2]) # transf. .distinct() # transf. ) # Só aqui o Spark EXECUTA tudo de uma vez ↓ print(f"Tipos únicos de erro: {erros.count()}") # AÇÃO! print(erros.collect()) # AÇÃO!

// QUIZ 02
🧠 Você quer filtrar linhas de um RDD com erros e contar quantas são. Qual sequência está correta?
✅ Correto! +50 XP. filter() é transformação (lazy), count() é ação (dispara execução). Sempre: transformações primeiro, ação no final.
❌ Lembre: você aplica transformações (filter, map) para definir o pipeline, depois dispara com uma ação (count, collect).
💡 Dica
Ações sempre vêm por último no pipeline. Qual dessas opções começa com uma transformação e termina com uma ação?

😴Lazy Evaluation — O segredo da eficiência do Spark

Spark NÃO executa nada quando você chama map() ou filter(). Ele apenas anota o que precisa ser feito (o DAG). Só quando você chama uma Ação é que o Spark otimiza e executa tudo de uma vez.

// QUIZ 03
🧠 Você escreveu: rdd2 = rdd.filter(lambda x: x > 0).map(lambda x: x * 2). Quando o Spark realmente processa os dados?
✅ Lazy Evaluation! +50 XP. O Spark apenas anota as transformações no DAG. Nenhum dado é movido até uma ação ser chamada — isso permite otimizações internas poderosas.
❌ filter() e map() apenas constroem o plano (DAG). A execução real só acontece com uma ação (count, collect, saveAsTextFile...).
💡 Dica
"Lazy" = preguiçoso. O Spark é "preguiçoso": só trabalha quando você insiste com uma ação. Antes disso, ele só faz anotações no caderno (DAG).

from pyspark import SparkContext # Inicia o SparkContext sc = SparkContext("local[*]", "MeuPrimeiroSparkColab") # Cria um RDD com uma lista de números numeros = sc.parallelize([1, 2, 3, 4, 5]) # Aplica transformações e ação resultado = numeros.map(lambda x: x * 2).reduce(lambda a, b: a + b) print(f"Resultado: {resultado}") # Esperado: 30 # Sempre feche o SparkContext ao terminar sc.stop()
