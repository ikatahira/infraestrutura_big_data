🏛️ OLTP vs OLAP
OLTP (Online Transaction Processing) — sistemas otimizados para muitas transações pequenas e rápidas (inserir um pedido, atualizar um estoque). É o dia a dia operacional de um sistema.

OLAP (Online Analytical Processing) — sistemas otimizados para consultas analíticas complexas sobre grandes volumes históricos (total de vendas por região nos últimos 3 anos). É aqui que Data Warehouses entram.

Data Warehouse — um repositório central, estruturado e otimizado para análise (diferente do Data Lake da Semana 14, que guarda dados brutos). Os dados chegam via ETL (Extract, Transform, Load) — o mesmo tipo de transformação que você já fez manualmente com MapReduce/Spark.

Data Lake vs Data Warehouse: o Data Lake guarda tudo, bruto, schema-on-read. O Data Warehouse guarda dados já limpos e estruturados, prontos para análise gerencial — muitas arquiteturas modernas usam os dois juntos (o Lake alimenta o Warehouse via ETL).

⭐ Modelo Estrela (Star Schema)
A forma mais comum de organizar um Data Warehouse:

Tabela Fato — no centro, guarda as métricas numéricas (valor da venda, quantidade) e chaves para as dimensões. Cada linha é um evento (uma venda específica).

Tabelas Dimensão — ao redor da fato, guardam os "atributos descritivos" (quem, o quê, quando, onde): dimensão Produto, dimensão Cliente, dimensão Tempo, dimensão Loja.

Por que "estrela" — visualmente, a tabela fato fica no centro conectada a várias dimensões ao redor, formando o formato de estrela — desenho intencional para consultas analíticas rápidas (menos JOINs que um modelo relacional tradicional totalmente normalizado).
