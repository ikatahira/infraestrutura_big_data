🌍 O que é Big Data? — Conceito e Motivação
⚡ +100 XP ⏱ ~15 min Conceitual 📋 Ementa: Conceitos de Big Data
🔒
▾
Antes de instalar qualquer ferramenta, precisamos entender por que o Big Data existe. O que há de diferente nos dados de hoje que tornou necessário criar um ecossistema completamente novo?
🎓 Conexão com a disciplina (IAL008): A ementa começa com "Conceitos de Big Data". Entender o porquê do Big Data é essencial para compreender cada ferramenta que instalaremos nas próximas semanas — o Hadoop, Spark, Kafka, MongoDB. Elas existem para resolver os problemas que você vai aprender agora.
🕰️ A Explosão dos Dados — Uma Linha do Tempo
Anos 1960–1980: Dados eram armazenados em mainframes. Poucos megabytes. Dados eram tão preciosos que eram armazenados com extremo cuidado.

Anos 1990–2000: A internet chegou. E-mails, websites, logs de servidores. Dados cresceram para gigabytes. Bancos de dados relacionais (MySQL, Oracle) conseguiam dar conta.

Anos 2005–2010: Redes sociais, smartphones, IoT. YouTube, Facebook, Twitter gerando terabytes por dia. Os bancos de dados tradicionais começaram a travar. Era necessária uma nova abordagem.

2011 em diante: Estimativa atual: 2,5 quintilhões de bytes de dados gerados por dia. Para ter ideia: 1 quintilhão = 1.000.000.000.000.000.000. O Google processa mais de 20 petabytes de dados por dia.
💡 Big Data — Definição
Big Data não é apenas "muito dado". É o conjunto de dados, ferramentas e técnicas para lidar com volumes, velocidades e variedades de dados que excedem a capacidade de sistemas tradicionais de capturar, armazenar, gerenciar e analisar.

A diferença fundamental: um banco de dados tradicional (MySQL) funciona em uma única máquina. O Big Data distribui o trabalho entre dezenas, centenas ou milhares de máquinas — que é exatamente o que o Hadoop (que você instalará na Semana 02) faz.
Aspecto Processamento Tradicional (RDBMS) Big Data (Hadoop/Spark)
Volume máximo Limitado a uma máquina (~TBs) Ilimitado (distribui entre nós)
Tipo de dados Estruturados (tabelas) Estruturados, semi-estruturados, não-estruturados
Escalabilidade Vertical (hardware mais caro) Horizontal (mais máquinas baratas)
Custo Alto (servidores especializados) Baixo (commodity hardware)
Velocidade de ingestão Limitada Streaming em tempo real possível
Falhas Críticas (single point of failure) Tolerante a falhas (replicação automática)

📊 Os 5Vs do Big Data — Na Prática
⚡ +100 XP ⏱ ~12 min Conceitual 📋 Ementa: Volume, Velocidade, Variedade, Veracidade, Valor
🔒
▾
Os 5Vs são o framework mais usado para caracterizar um problema de Big Data. Se seus dados apresentam essas características, você precisa de ferramentas como Hadoop ou Spark. Vamos ver cada um com exemplos reais.
🎓 Conexão com a disciplina (IAL008): Os 5Vs são diretamente citados na ementa: "Características dos dados: Volume, Velocidade, Variedade, Veracidade e Valor". Ao longo do semestre, cada ferramenta que você aprender ataca um ou mais desses Vs — o HDFS resolve o Volume, o Kafka resolve a Velocidade, o MongoDB resolve a Variedade.
📦
V
Volume
Quantidade massiva de dados. Facebook gera 100+ PB de logs por dia. O HDFS distribui esses dados em blocos de 128 MB entre vários nós.
⚡
V
Velocidade
Dados chegam em alta velocidade e precisam ser processados rapidamente. Twitter: 500.000+ tweets por minuto. Solução: Apache Kafka (Semana 09).
🎨
V
Variedade
Dados em múltiplos formatos: JSON, CSV, vídeo, imagem, áudio, logs. Os bancos NoSQL como MongoDB (Semana 07) lidam bem com essa diversidade.
🔍
V
Veracidade
Qualidade e confiabilidade dos dados. Dados de sensores IoT podem ter leituras incorretas. Dados de redes sociais são frequentemente imprecisos ou contraditórios.
💎
V
Valor
Extrair insights úteis dos dados brutos. Ter petabytes de dados sem análise não tem valor. O objetivo final de toda a infraestrutura que vamos aprender.
🏭 Exemplo Real: Como a Netflix usa os 5Vs
Volume: 250 milhões de usuários. Cada visualização gera eventos de clique, pause, rebobinar, classificação — bilhões de eventos por dia.

Velocidade: Em tempo real, o sistema detecta que você pausou um vídeo 3 vezes no mesmo ponto e sugere um conteúdo similar.

Variedade: Dados estruturados (histórico de visualização), semi-estruturados (metadados JSON dos filmes), não-estruturados (miniaturas de vídeos analisadas por visão computacional).

Veracidade: Filtrar bots que assistem conteúdo artificialmente para inflar métricas.

Valor: 80% do conteúdo assistido na Netflix vem de recomendações — não de busca direta. Todo o ecossistema de Big Data existe para gerar esse valor.

🏛️ Os 3 Pilares do Hadoop
1. HDFS (Hadoop Distributed File System) — Semana 02
O sistema de arquivos distribuído. Divide arquivos em blocos de 128 MB e os distribui entre múltiplas máquinas. Cada bloco é replicado 3 vezes para tolerar falhas. Se uma máquina cair, os dados ainda estão disponíveis nas outras cópias.

Analogia: Imagine que você tem um livro de 300 páginas. O HDFS divide em 3 partes (blocos de 100 páginas cada) e guarda cada parte em 3 armários diferentes. Se um armário quebrar, você ainda tem 2 cópias de cada parte.

2. MapReduce — Semana 03
O modelo de programação distribuída. Divide o processamento em duas fases: Map (processar cada bloco de dados em paralelo) e Reduce (combinar os resultados parciais). O Google usou esse modelo para construir seu índice de busca.

Analogia: Contar palavras em 1000 livros. Map: dê 10 livros para cada um de 100 alunos — cada aluno conta as palavras em seus livros. Reduce: um coordenador soma todos os resultados parciais.

3. YARN (Yet Another Resource Negotiator) — Semana 02
O gerenciador de recursos do cluster. Decide qual máquina vai executar qual tarefa, evitando sobrecarga. É o "sistema operacional" do cluster Hadoop.
🗺️ O Ecossistema Completo — O que você vai aprender este semestre
O Hadoop por si só é a fundação. Sobre ele, existe um ecossistema de ferramentas:

Apache Spark (Semanas 04–05): Processamento in-memory, até 100x mais rápido que MapReduce. É o padrão moderno para processamento de Big Data.

Apache Kafka (Semana 09): Streaming de dados em tempo real. Recebe milhões de eventos por segundo e os distribui para processamento imediato.

MongoDB (Semana 07): Banco de dados orientado a documentos (NoSQL). Armazena JSON nativamente — ideal para dados semi-estruturados.

Apache Cassandra (Semana 08): Banco de dados colunar distribuído. Altamente disponível — nunca há um único ponto de falha.

AWS EMR, S3 (Semanas 11–13): A mesma infraestrutura, na nuvem. Sem precisar gerenciar hardware.

Todas as ferramentas Big Data que você vai instalar neste semestre rodam em Linux. O Ubuntu 22.04 LTS (Long-Term Support) garante suporte até abril de 2027 e é a distribuição mais usada em servidores de Big Data. O sufixo "LTS" significa que você não terá quebras inesperadas por atualizações.
01
Baixar e Instalar o VirtualBox
Acesse virtualbox.org/wiki/Downloads e baixe a versão para o seu sistema operacional (Windows, macOS ou Linux). Durante a instalação, aceite todas as opções padrão.
ℹ️ Requisitos mínimos: 8 GB de RAM (4 GB para o host + 4 GB para a VM), 40 GB de espaço em disco, processador com suporte a virtualização (VT-x ou AMD-V — ative no BIOS se necessário).
02
Baixar a ISO do Ubuntu 22.04 LTS
Acesse releases.ubuntu.com/22.04/ e baixe o arquivo ubuntu-22.04.x-desktop-amd64.iso. O arquivo tem aproximadamente 4 GB.
03
Criar a Máquina Virtual no VirtualBox
No VirtualBox, clique em Novo. Configure: Nome: BigData-Ubuntu, Tipo: Linux, Versão: Ubuntu (64-bit), RAM: 4096 MB (4 GB), Disco: 40 GB (dinâmico).
⚠️ Configure pelo menos 2 CPUs nas configurações da VM (aba Sistema → Processador). O Hadoop precisa de múltiplos núcleos para simular o ambiente distribuído.
04
Instalar o Ubuntu 22.04
Na VM criada, vá em Configurações → Armazenamento → clique no ícone de disco → "Escolher arquivo de disco óptico virtual" → selecione a ISO baixada. Inicie a VM e siga o instalador do Ubuntu (escolha "Instalação Mínima" para economizar espaço).

01
Criar um arquivo CSV (dados estruturados)
CSV (Comma-Separated Values) é o formato mais simples de dados estruturados. Vamos criar um dataset fictício de vendas e explorá-lo com comandos Linux.
bash — Ubuntu 22.04 e WSL2
# mkdir -p = cria diretórios (e subdiretórios) sem erro se já existirem # ~ = atalho para seu diretório home (/home/seu_usuario) $ mkdir -p ~/bigdata/semana01 $ cd ~/bigdata/semana01 # cat > arquivo << 'EOF'...EOF = cria arquivo com o conteúdo entre os marcadores # Esta técnica se chama "heredoc" — muito usada em scripts shell $ cat > vendas.csv << 'EOF' id,produto,categoria,preco,quantidade,data 1,Notebook,Eletrônicos,3500.00,2,2024-01-15 2,Cadeira Gamer,Móveis,850.50,5,2024-01-15 3,Monitor 4K,Eletrônicos,1200.00,3,2024-01-16 4,Teclado Mecânico,Periféricos,320.00,10,2024-01-16 5,Smartphone,Eletrônicos,2800.00,8,2024-01-17 6,Mesa de Escritório,Móveis,650.00,2,2024-01-17 7,Headset,Periféricos,180.00,15,2024-01-18 8,Webcam HD,Periféricos,220.00,7,2024-01-18 EOF
02
Explorar o CSV com comandos Linux
Sem nenhuma ferramenta especial, apenas com comandos padrão do Linux, você pode fazer análises básicas em arquivos de dados.
bash — Ubuntu 22.04 e WSL2
# cat = exibe todo o conteúdo do arquivo $ cat vendas.csv # wc -l = conta linhas do arquivo (word count, linha) $ wc -l vendas.csv # head -3 = exibe apenas as primeiras 3 linhas $ head -3 vendas.csv # grep = filtra linhas que contêm o texto especificado # Equivalente a um WHERE em SQL! $ grep "Eletrônicos" vendas.csv # cut -d',' -f2,3 = recorta colunas 2 e 3 usando vírgula como separador # -d = delimiter (separador), -f = fields (campos/colunas) $ cut -d',' -f2,3 vendas.csv # sort = ordena as linhas # -t',' = separador vírgula, -k4 = ordenar pela coluna 4 (preço) # -n = numérico, -r = reverso (maior primeiro) # | head -5 = pegar apenas os 5 primeiros (pipe = conecta saída de um comando à entrada do próximo) $ sort -t',' -k4 -n -r vendas.csv | head -5
✅ Saída do sort (top 5 por preço)
1,Notebook,Eletrônicos,3500.00,2,2024-01-15 5,Smartphone,Eletrônicos,2800.00,8,2024-01-17 3,Monitor 4K,Eletrônicos,1200.00,3,2024-01-16 2,Cadeira Gamer,Móveis,850.50,5,2024-01-15 6,Mesa de Escritório,Móveis,650.00,2,2024-01-17
💡 Os comandos grep, sort, cut e | (pipe) são equivalentes às cláusulas WHERE, ORDER BY, SELECT e subconsultas do SQL — mas funcionam em qualquer arquivo de texto, sem precisar de banco de dados!
03
Criar um arquivo JSON (dados semi-estruturados)
JSON (JavaScript Object Notation) é o formato semi-estruturado mais comum. Diferente do CSV, cada registro pode ter campos diferentes — ideal para dados heterogêneos como os do MongoDB (Semana 07).
bash — Ubuntu 22.04 e WSL2
$ cat > produtos.json << 'EOF' [ {"id": 1, "nome": "Notebook", "specs": {"ram": "16GB", "ssd": "512GB"}, "tags": ["trabalho", "portatil"]}, {"id": 2, "nome": "Smartphone", "specs": {"armazenamento": "256GB", "camera": "108MP"}, "preco_usd": 750}, {"id": 3, "nome": "Cadeira Gamer", "material": "couro_sintetico", "max_kg": 120} ] EOF # Observe: cada produto tem campos DIFERENTES! # Notebook tem "specs.ram" e "tags" # Smartphone tem "specs.camera" e "preco_usd" # Cadeira tem "material" e "max_kg" # Isso seria impossível em uma tabela SQL sem muitas colunas vazias # É por isso que o MongoDB (NoSQL) existe! # Contar quantos produtos existem $ grep -c '"id"' produtos.json # Extrair apenas os nomes $ grep -o '"nome": "[^"]*"' produtos.json
