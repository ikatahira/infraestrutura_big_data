M1
🔧 Preparar o Sistema — Java e Dependências
⚡ +100 XP ⏱ ~8 min Instalação 📋 Ementa: Recursos de hardware e SO para Big Data
🔒
▾
O Hadoop é escrito em Java, então precisamos instalar o Java Development Kit (JDK) antes de qualquer coisa. Também vamos criar um usuário dedicado chamado hadoop para rodar o cluster de forma segura.
🎓 Conexão com a disciplina (IAL008): A ementa cita "Recursos de hardware para Big Data" e "Conceito de sistemas operacionais para bancos de dados distribuídos". Instalar o Java e configurar o usuário do sistema são as primeiras decisões de infraestrutura de um ambiente Big Data — equivalem a preparar o sistema operacional para receber a camada de software distribuído.
01
Atualizar o sistema
Sempre atualize a lista de pacotes antes de instalar qualquer software. Isso garante que você receberá as versões mais recentes e seguras.
bash
$ sudo apt update
ℹ️ O que faz: apt update baixa a lista de pacotes disponíveis. só para saber: apt upgrade -y instala as atualizações disponíveis sem pedir confirmação (-y = "yes" automático).
02
Instalar o Java JDK 11
O Hadoop 3.x é compatível com Java 8 e Java 11. Vamos instalar o OpenJDK 11, que é o padrão no Ubuntu 22.04.
bash
$ sudo apt install openjdk-11-jdk -y
⚠️ Isso pode demorar alguns minutos dependendo da velocidade da internet. Aguarde até o prompt retornar!
03
Verificar a instalação do Java
Confirme que o Java foi instalado corretamente e veja qual versão está ativa.
bash
$ java -version
✅ Saída esperada
openjdk version "11.0.xx" 20xx-xx-xx OpenJDK Runtime Environment (build 11.0.xx+xx-Ubuntu-...) OpenJDK 64-Bit Server VM (build 11.0.xx+xx-Ubuntu-..., mixed mode, sharing)
04
Criar o usuário hadoop
É uma boa prática rodar o Hadoop com um usuário dedicado, separando os processos do sistema dos processos do cluster.
bash
$ sudo adduser hadoop
ℹ️ O sistema pedirá uma senha para o novo usuário. Digite uma senha fácil de lembrar (ex: hadoop123). Confirme os dados e pressione Enter nas perguntas opcionais.
05
Adicionar o usuário hadoop ao grupo sudo
Para que o usuário hadoop possa executar comandos administrativos quando necessário.
bash
$ sudo usermod -aG sudo hadoop
06
Mudar para o usuário hadoop
A partir de agora, todos os passos de instalação serão executados como o usuário hadoop.
bash
$ su - hadoop
✅ Após este comando, o prompt mudará para hadoop@... — isso significa que você está operando como o usuário hadoop!

M2
🔑 Configurar SSH sem Senha
⚡ +80 XP ⏱ ~5 min SSH 📋 Ementa: Segurança de SO para Big Data
🔒
▾
O Hadoop precisa comunicar-se entre os nós via SSH. Em modo pseudo-distribuído (um só computador), ele precisa se conectar a si mesmo sem precisar digitar senha. Vamos configurar isso com chaves SSH.
🎓 Conexão com a disciplina (IAL008): A ementa inclui "Desempenho e segurança de sistemas operacionais para Big Data". A autenticação SSH por chaves é o mecanismo de segurança que permite ao cluster se autogerenciar — iniciar e parar serviços nos nós — sem expor senhas em texto plano. Em um cluster real com dezenas de máquinas, este mesmo mecanismo protege toda a comunicação entre os nós.
01
Instalar o SSH
Instala o servidor e cliente OpenSSH se ainda não estiverem presentes no sistema.
bash
$ sudo apt install openssh-server openssh-client -y
02
Gerar o par de chaves SSH
Este comando gera uma chave privada (id_rsa) e uma chave pública (id_rsa.pub) na pasta ~/.ssh/. Pressione Enter em todas as perguntas para aceitar os padrões.
bash
$ ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa
ℹ️ -t rsa = tipo RSA | -P '' = senha vazia (sem senha) | -f ~/.ssh/id_rsa = caminho do arquivo de saída
03
Adicionar a chave pública às chaves autorizadas
Para que o localhost aceite conexões SSH sem senha, adicionamos a chave pública ao arquivo authorized_keys.
bash
$ cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
04
Ajustar as permissões do diretório .ssh
O SSH é muito rigoroso com permissões de arquivo. Permissões incorretas fazem a autenticação falhar.
bash
$ chmod 600 ~/.ssh/authorized_keys
05
Testar a conexão SSH sem senha
Tente conectar ao localhost. Na primeira vez, o sistema perguntará se você confia no host — digite yes e pressione Enter. Se não pedir senha em seguida, a configuração está correta!
bash
$ ssh localhost
✅ Saída esperada (na 1ª vez)
The authenticity of host 'localhost (127.0.0.1)' can't be established. ... Are you sure you want to continue connecting (yes/no/[fingerprint])? yes Warning: Permanently added 'localhost' (ED25519) to the list of known hosts. Welcome to Ubuntu 22.04...
⚠️ Após conectar, você estará dentro de uma nova sessão SSH. Digite exit para voltar antes de continuar!
bash
$ exit

M3
📦 Baixar e Instalar o Hadoop 3.3
⚡ +100 XP ⏱ ~10 min Download 📋 Ementa: Ferramentas de armazenamento de grandes massas de dados
🔒
▾
Agora vamos baixar o Hadoop diretamente do site oficial Apache e instalá-lo no sistema. Faremos o download, extrairemos o arquivo e moveremos para a pasta correta.
🎓 Conexão com a disciplina (IAL008): O objetivo da disciplina é "Identificar as opções de implementação dos sistemas operacionais e dos recursos de hardware necessários". O Hadoop é a principal ferramenta que transforma um sistema operacional Linux em um sistema de armazenamento de grandes massas de dados — exatamente como descrito na ementa. Você está instalando a infraestrutura de base de um ecossistema Big Data real.
01
Baixar o Hadoop 3.3.6
Usamos o wget para baixar diretamente do servidor Apache. O arquivo tem aproximadamente 650 MB.
bash
$ wget https://downloads.apache.org/hadoop/common/hadoop-3.3.6/hadoop-3.3.6.tar.gz
⚠️ O download pode demorar vários minutos. Se a URL falhar, acesse hadoop.apache.org/releases.html para obter o link da versão mais recente.
02
Extrair o arquivo comprimido
O arquivo .tar.gz é um pacote comprimido. Vamos extraí-lo na pasta /usr/local/.
bash
$ sudo tar xzf hadoop-3.3.6.tar.gz -C /usr/local/
ℹ️ x = extrair | z = descomprimir gzip | f = especificar arquivo | -C = diretório de destino
03
Renomear a pasta para um nome mais curto
Por convenção, renomeamos o diretório para apenas hadoop, facilitando referências futuras.
bash
$ sudo mv /usr/local/hadoop-3.3.6 /usr/local/hadoop
04
Mudar o dono da pasta para o usuário hadoop
O usuário hadoop precisa de permissão de escrita no diretório de instalação para iniciar e parar os serviços.
bash
$ sudo chown -R hadoop:hadoop /usr/local/hadoop
ℹ️ chown = "change owner" | -R = recursivo (aplica em todos os arquivos internos)
05
Verificar a instalação
Verifique que o diretório Hadoop existe e está correto.
bash
$ ls /usr/local/hadoop
✅ Saída esperada
bin etc include lib libexec LICENSE.txt NOTICE.txt README.txt sbin share

M4
⚙️ Configurar Variáveis de Ambiente
⚡ +80 XP ⏱ ~8 min Configuração 📋 Ementa: Modos de configuração de sistemas Big Data
🔒
▾
O sistema precisa saber onde o Hadoop e o Java estão instalados. Fazemos isso configurando variáveis de ambiente no arquivo ~/.bashrc, que é executado toda vez que um terminal é aberto.
🎓 Conexão com a disciplina (IAL008): A ementa destaca "Modos de configuração e funcionamento de um sistema para Big Data". Configurar variáveis de ambiente é o mecanismo pelo qual o sistema operacional e o software Big Data se integram — o Linux precisa "saber" onde o Hadoop está para que os scripts de inicialização do cluster funcionem. Esta etapa representa a integração entre SO e ferramenta distribuída.
01
Descobrir o caminho do Java
Precisamos saber exatamente onde o Java está instalado para informar ao Hadoop.
bash
$ readlink -f $(which java) | sed "s|/bin/java||"
✅ Saída esperada
/usr/lib/jvm/java-11-openjdk-amd64
ℹ️ Anote este caminho! Você vai precisar dele no próximo passo. Em sistemas ARM (como Apple M1/M2 com VM), o caminho pode ser diferente.
02
Editar o arquivo ~/.bashrc
Vamos abrir o arquivo de configuração do shell com o editor nano e adicionar as variáveis ao final do arquivo.
bash
$ nano ~/.bashrc
⚠️ No editor nano: use as setas do teclado para navegar, Ctrl+End para ir ao final do arquivo, e depois adicione as linhas abaixo.
03
Adicionar as variáveis no final do arquivo
Cole o bloco abaixo no final do arquivo ~/.bashrc. Ajuste o caminho do JAVA_HOME se necessário.
~/.bashrc (adicionar no final)
# ===== HADOOP ENVIRONMENT ===== export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64 export HADOOP_HOME=/usr/local/hadoop export HADOOP_INSTALL=$HADOOP_HOME export HADOOP_MAPRED_HOME=$HADOOP_HOME export HADOOP_COMMON_HOME=$HADOOP_HOME export HADOOP_HDFS_HOME=$HADOOP_HOME export YARN_HOME=$HADOOP_HOME export HADOOP_COMMON_LIB_NATIVE_DIR=$HADOOP_HOME/lib/native export PATH=$PATH:$HADOOP_HOME/sbin:$HADOOP_HOME/bin export HADOOP_OPTS="-Djava.library.path=$HADOOP_HOME/lib/native"
ℹ️ Para salvar no nano: Ctrl+X → Y → Enter
04
Recarregar as configurações
O comando source recarrega o arquivo sem precisar fechar e reabrir o terminal.
bash
$ source ~/.bashrc
05
Verificar as variáveis
Confirme que as variáveis foram definidas corretamente.
bash
$ echo $HADOOP_HOME $ echo $JAVA_HOME $ hadoop version
✅ Saída esperada
/usr/local/hadoop /usr/lib/jvm/java-11-openjdk-amd64 Hadoop 3.3.6 Source code repository ... Compiled by ubuntu on ...

M5
📝 Configurar os Arquivos XML do Hadoop
⚡ +120 XP ⏱ ~12 min Configuração XML 📋 Ementa: Modos de configuração e funcionamento
🔒
▾
Esta é a missão mais importante! O Hadoop usa arquivos XML para saber como deve operar. Configuraremos 4 arquivos que definem o cluster, o HDFS, o YARN e o MapReduce.
🎓 Conexão com a disciplina (IAL008): Aqui você está diretamente praticando o objetivo: "Implementar e configurar sistemas operacionais usados para armazenamento de grandes quantidades de dados". Cada arquivo XML reflete uma camada da arquitetura: core-site.xml (SO/rede), hdfs-site.xml (armazenamento distribuído), mapred-site.xml (processamento distribuído) e yarn-site.xml (gerenciamento de recursos) — juntos, formam o "modo de configuração" do sistema Big Data.
01
Configurar hadoop-env.sh — Caminho do Java para o Hadoop
Este arquivo diz ao Hadoop onde o Java está instalado. Abra o arquivo e adicione a variável JAVA_HOME.
bash
$ nano /usr/local/hadoop/etc/hadoop/hadoop-env.sh
ℹ️ No arquivo, encontre a linha #export JAVA_HOME= (com #), remova o # e adicione o caminho. Ou simplesmente vá ao final e adicione a linha abaixo:
hadoop-env.sh
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
02
Configurar core-site.xml — Endereço do NameNode
Este arquivo define o endereço e porta do NameNode (o servidor principal do HDFS) e onde ficam os arquivos temporários.
bash
$ nano /usr/local/hadoop/etc/hadoop/core-site.xml
⚠️ O arquivo já tem a tag <configuration></configuration>. Você deve substituir o conteúdo entre essas tags pelo conteúdo abaixo.
core-site.xml
<configuration> <property> <name>hadoop.tmp.dir</name> <value>/home/hadoop/tmpdata</value> </property> <property> <name>fs.default.name</name> <value>hdfs://localhost:9000</value> </property> </configuration>
ℹ️ hadoop.tmp.dir = pasta para dados temporários | fs.default.name = endereço do sistema de arquivos padrão (HDFS rodando na porta 9000)
03
Configurar hdfs-site.xml — Replicação e Caminhos dos Nós
Define onde o NameNode e DataNode armazenam seus dados, e o fator de replicação. Em pseudo-distribuído usamos replication=1 porque temos apenas um nó.
bash
$ nano /usr/local/hadoop/etc/hadoop/hdfs-site.xml
hdfs-site.xml
<configuration> <property> <name>dfs.data.dir</name> <value>/home/hadoop/dfsdata/namenode</value> </property> <property> <name>dfs.data.dir</name> <value>/home/hadoop/dfsdata/datanode</value> </property> <property> <name>dfs.replication</name> <value>1</value> </property> </configuration>
04
Configurar mapred-site.xml — Framework do MapReduce
Diz ao Hadoop para usar o YARN como gerenciador de recursos para os jobs MapReduce.
bash
$ nano /usr/local/hadoop/etc/hadoop/mapred-site.xml
mapred-site.xml
<configuration> <property> <name>mapreduce.framework.name</name> <value>yarn</value> </property> </configuration>
05
Configurar yarn-site.xml — Gerenciador de Recursos
Configura o YARN (Yet Another Resource Negotiator), que gerencia a distribuição de recursos entre os jobs do cluster.
bash
$ nano /usr/local/hadoop/etc/hadoop/yarn-site.xml
yarn-site.xml
<configuration> <property> <name>yarn.nodemanager.aux-services</name> <value>mapreduce_shuffle</value> </property> <property> <name>yarn.nodemanager.aux-services.mapreduce.shuffle.class</name> <value>org.apache.hadoop.mapred.ShuffleHandler</value> </property> <property> <name>yarn.resourcemanager.hostname</name> <value>localhost</value> </property> </configuration>

M6
🚀 Formatar e Iniciar o Cluster HDFS
⚡ +120 XP ⏱ ~8 min Deploy 📋 Ementa: Clusters computacionais e processamento distribuído
🔒
▾
Chegou a hora de ligar o cluster! Primeiro formatamos o NameNode (como formatar um HD pela primeira vez), depois iniciamos todos os serviços HDFS e YARN.
🎓 Conexão com a disciplina (IAL008): A ementa fala em "Ferramentas que implementem o processamento distribuído, usado em clusters computacionais". Ao rodar start-dfs.sh e start-yarn.sh, você está ativando exatamente um cluster computacional com processamento distribuído — mesmo que seja em um único computador. O modo pseudo-distribuído simula toda a arquitetura de um cluster real, sendo o passo essencial antes de operar em ambiente totalmente distribuído (próximas semanas).
01
Criar os diretórios necessários
Criamos as pastas que configuramos nos arquivos XML.
bash
$ mkdir -p ~/tmpdata $ mkdir -p ~/dfsdata/namenode $ mkdir -p ~/dfsdata/datanode
02
Formatar o NameNode
Este comando inicializa o sistema de arquivos do HDFS pela primeira vez. É como formatar um disco rígido — só deve ser feito uma vez! Se você rodar novamente depois, perderá todos os dados do HDFS.
bash
$ hdfs namenode -format
⛔ ATENÇÃO: Execute este comando APENAS UMA VEZ! Reformatar o NameNode apaga todos os metadados do HDFS!
✅ Saída esperada (final)
... Storage directory /home/hadoop/dfsdata/namenode has been successfully formatted. ...
03
Iniciar os serviços HDFS
Este script inicia o NameNode, o DataNode e o Secondary NameNode. São os três processos principais do HDFS.
bash
$ start-dfs.sh
✅ Saída esperada
Starting namenodes on [localhost] Starting datanodes Starting secondary namenodes [seu-hostname]
04
Iniciar os serviços YARN
Inicia o ResourceManager e o NodeManager, que gerenciam os recursos do cluster para execução de jobs.
bash
$ start-yarn.sh
✅ Saída esperada
Starting resourcemanager Starting nodemanagers
05
Verificar os processos em execução com jps
O comando jps (Java Virtual Machine Process Status) lista todos os processos Java em execução. Você deve ver 5 processos rodando!
bash
$ jps
✅ Saída esperada — 5 processos!
12345 NameNode 12346 DataNode 12347 SecondaryNameNode 12348 ResourceManager 12349 NodeManager 12350 Jps
⚠️ Se algum processo não aparecer, verifique os logs em /usr/local/hadoop/logs/ para identificar o erro.
06
Acessar a interface web do Hadoop
O Hadoop oferece uma interface web para monitoramento. Abra seu navegador e acesse os endereços abaixo.
🌐
localhost:9870
NameNode Web UI
Monitoramento HDFS
📊
localhost:8088

📂 Operações Básicas no HDFS
⚡ +100 XP ⏱ ~10 min HDFS Commands 📋 Ementa: Armazenamento de grandes massas de dados
🔒
▾
O cluster está rodando! Agora vamos aprender os comandos essenciais do HDFS para criar diretórios, enviar arquivos, listar e baixar dados do sistema de arquivos distribuído.
🎓 Conexão com a disciplina (IAL008) — Atividade 2 (3,0 pts): Esta missão é a base direta da Atividade 2: "Executar 10 comandos HDFS diferentes e documentar resultados". Ao dominar -put, -get, -ls, -mkdir, -cat, -rm, -df, -du, -tail e fsck, você estará operando o HDFS como um engenheiro de dados — não apenas instalando, mas usando a ferramenta de armazenamento distribuído prevista na ementa.
01
Listar a raiz do HDFS
Veja o que existe na raiz (/) do sistema de arquivos distribuído.
bash
$ hdfs dfs -ls /
02
Criar um diretório no HDFS
Criamos uma estrutura de diretórios no HDFS para organizar os dados do usuário.
bash
$ hdfs dfs -mkdir /user $ hdfs dfs -mkdir /user/hadoop $ hdfs dfs -mkdir /user/hadoop/dados
03
Criar um arquivo local de teste
Criamos um arquivo de texto no sistema de arquivos local (não no HDFS ainda) para depois enviarmos ao cluster.
bash
$ echo "Olá, Hadoop HDFS! Este é meu primeiro arquivo no cluster Big Data." > ~/teste.txt $ cat ~/teste.txt
04
Enviar o arquivo ao HDFS (put)
O comando -put (ou -copyFromLocal) copia um arquivo do sistema local para o HDFS.
bash
$ hdfs dfs -put ~/teste.txt /user/hadoop/dados/
05
Verificar o arquivo no HDFS
Confirme que o arquivo foi enviado corretamente.
bash
$ hdfs dfs -ls /user/hadoop/dados/
✅ Saída esperada
Found 1 items -rw-r--r-- 1 hadoop supergroup 68 2024-xx-xx xx:xx /user/hadoop/dados/teste.txt
06
Ler o conteúdo do arquivo no HDFS
O comando -cat exibe o conteúdo de um arquivo diretamente do HDFS.
bash
$ hdfs dfs -cat /user/hadoop/dados/teste.txt
07
Ver informações detalhadas (fsck)
O comando fsck mostra detalhes técnicos do arquivo no HDFS, incluindo em quantos blocos está dividido e quais DataNodes armazenam cada bloco.
bash
$ hdfs fsck /user/hadoop/dados/teste.txt -files -blocks -locations
08
Verificar o espaço em disco do HDFS
Similar ao comando df do Linux, mas para o HDFS.
bash
$ hdfs dfs -df -h /
09
Para parar o cluster (quando quiser)
Quando você terminar de trabalhar com o Hadoop, use os comandos abaixo para desligar os serviços de forma segura.
bash
$ stop-yarn.sh $ stop-dfs.sh
✅ Para religar, basta rodar start-dfs.sh e start-yarn.sh novamente — sem precisar formatar o NameNode!

🛠️ Guia de Troubleshooting — Erros Mais Comuns

Encontrou um problema? Clique no erro correspondente abaixo para ver a causa e a solução passo a passo. Todos os erros listados aqui são reais e frequentemente encontrados por alunos durante a instalação.

🎓 Conexão com a disciplina (IAL008): Diagnosticar e corrigir falhas em sistemas distribuídos é uma competência central da ementa — "Desempenho e segurança de sistemas operacionais para Big Data". Entender por que um DataNode não inicia ou por que o SSH falha é parte essencial do conhecimento de operação de infraestrutura Big Data, não apenas da instalação.
🔴
Erro: ssh: connect to host localhost port 22: Connection refused
Missão 2 — SSH Muito Comum
▾
Causa: O servidor SSH (openssh-server) não está instalado ou o serviço sshd não está em execução. O Ubuntu Desktop frequentemente vem apenas com o cliente SSH, sem o servidor.
D1
Diagnóstico — Verificar se o SSH está instalado e rodando
bash
$ sudo systemctl status ssh
❌ Se você ver isso (problema):
Unit ssh.service could not be found. — ou — Active: inactive (dead)
✔
Solução — Instalar e iniciar o servidor SSH
bash
$ sudo apt install openssh-server -y $ sudo systemctl enable ssh # inicia automaticamente no boot $ sudo systemctl start ssh $ sudo systemctl status ssh # deve mostrar "active (running)"
✅ Após instalar e iniciar o SSH, tente novamente ssh localhost. Na primeira conexão, confirme com yes e verifique que não pede senha.
D2
Causa alternativa — Firewall bloqueando a porta 22
bash
$ sudo ufw status # verificar estado do firewall $ sudo ufw allow ssh # liberar SSH no firewall $ sudo ufw allow 22 # alternativa explícita
🔴
Erro: Permission denied (publickey) ao rodar start-dfs.sh
Missão 2 — SSH Muito Comum
▾
Causa: A chave pública SSH não foi adicionada ao arquivo authorized_keys, ou as permissões dos arquivos estão incorretas. O SSH é muito rigoroso com permissões — qualquer arquivo com permissão "muito aberta" é rejeitado.
✔
Solução — Reconfigurar chaves e permissões
bash
$ ls -la ~/.ssh/ # verificar se a chave existe # Se id_rsa.pub não existir, gere novamente: $ ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa $ cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys # Corrigir permissões (OBRIGATÓRIO) $ chmod 700 ~/.ssh $ chmod 600 ~/.ssh/authorized_keys $ chmod 600 ~/.ssh/id_rsa $ chmod 644 ~/.ssh/id_rsa.pub $ ssh localhost # testar novamente
D1
Causa alternativa — Hadoop versão 3.x requer o pacote pdsh
O Hadoop 3.x usa pdsh (Parallel Distributed Shell) para gerenciar conexões. Se não estiver instalado, o SSH pode falhar com erros estranhos.
bash
$ sudo apt install pdsh -y $ export PDSH_RCMD_TYPE=ssh $ echo 'export PDSH_RCMD_TYPE=ssh' >> ~/.bashrc # tornar permanente

Erro: JAVA_HOME is not set ou Error: Invalid JAVA_HOME
Missão 4 — Variáveis Comum
▾
Causa: O caminho do Java no ~/.bashrc ou no hadoop-env.sh está incorreto, ou o source ~/.bashrc não foi executado após a edição. Em sistemas ARM (VM Apple M1/M2), o caminho é diferente (aarch64 em vez de amd64).
D1
Diagnóstico — Descobrir o caminho correto do Java
bash
$ readlink -f $(which java) # Resultado exemplo: /usr/lib/jvm/java-11-openjdk-amd64/bin/java # O JAVA_HOME é o caminho SEM /bin/java no final! $ update-alternatives --list java # Mostra todas as versões instaladas
✔
Solução — Corrigir o JAVA_HOME nos dois arquivos
bash
# 1. Descobrir o caminho correto automaticamente $ export JAVA_HOME=$(readlink -f $(which java) | sed "s|/bin/java||") $ echo $JAVA_HOME # anote este valor! # 2. Corrija a linha no ~/.bashrc com o caminho correto $ nano ~/.bashrc # 3. Corrija também o hadoop-env.sh $ nano /usr/local/hadoop/etc/hadoop/hadoop-env.sh # 4. Recarregar $ source ~/.bashrc $ echo $JAVA_HOME # deve mostrar o caminho correto
⚠️ ARM (Apple M1/M2/M3 via VM): o caminho pode ser /usr/lib/jvm/java-11-openjdk-arm64 — note arm64 em vez de amd64.
🔴
Erro: DataNode não aparece no jps após start-dfs.sh
Missão 6 — Iniciar Cluster Muito Comum
▾
Causa mais comum: O NameNode foi formatado mais de uma vez (hdfs namenode -format rodou duas vezes). Isso gera um novo clusterID no NameNode, que fica incompatível com o clusterID antigo gravado na pasta do DataNode — resultando no erro "Incompatible clusterIDs".
D1
Diagnóstico — Verificar o log do DataNode
bash
$ cat /usr/local/hadoop/logs/hadoop-hadoop-datanode-*.log | tail -30
❌ Mensagem que confirma o problema:
FATAL: Incompatible clusterIDs in /home/hadoop/dfsdata/datanode: namenode clusterID = CID-xxxxxxxx-xxxx datanode clusterID = CID-yyyyyyyy-yyyy
✔
Solução — Limpar os dados antigos e reformatar
Pare tudo, delete os dados antigos do DataNode e NameNode, e formate apenas uma vez.
bash
# Passo 1: Parar todos os serviços $ stop-all.sh # Passo 2: Apagar os dados corrompidos $ rm -rf ~/dfsdata/namenode/* $ rm -rf ~/dfsdata/datanode/* $ rm -rf ~/tmpdata/* # Passo 3: Formatar o NameNode UMA ÚNICA VEZ $ hdfs namenode -format # Passo 4: Reiniciar $ start-dfs.sh $ start-yarn.sh # Passo 5: Verificar — deve mostrar 5 processos $ jps
⛔ Atenção: este procedimento apaga todos os dados do HDFS. Use apenas durante a configuração inicial, quando ainda não há dados importantes no cluster.
🟠
Erro: bad conf file: element not <property> ao iniciar o cluster
Missão 5 — XML Config Comum
▾
Causa: Um dos arquivos XML de configuração (core-site.xml, hdfs-site.xml, etc.) contém um erro de sintaxe: tag não fechada, tag com nome errado, ou conteúdo extra fora do <configuration>.
D1
Diagnóstico — Verificar qual arquivo XML está com problema
bash
$ cat /usr/local/hadoop/etc/hadoop/core-site.xml $ cat /usr/local/hadoop/etc/hadoop/hdfs-site.xml
✔
Solução — Estrutura XML correta obrigatória
Cada propriedade deve seguir exatamente esta estrutura. Verifique se todas as tags estão abertas E fechadas corretamente.
Estrutura XML correta
<?xml version="1.0" encoding="UTF-8"?> <?xml-stylesheet type="text/xsl" href="configuration.xsl"?> <configuration> <property> <name>nome.da.propriedade</name> <!-- atenção: <name> não <n> --> <value>valor</value> </property> </configuration>
⚠️ Erro muito comum: usar <n> em vez de <name> — especialmente ao copiar de algum lugar que renderizou o HTML! O tag correto é sempre <name>...</name>.

🟡
Interface web localhost:9870 ou localhost:8088 não abre no navegador
Missão 6 — Web UI Comum em VMs
▾
Causas possíveis: (1) O cluster não está rodando (verifique com jps). (2) Você está em uma VM e tentando acessar do host — precisa usar o IP da VM. (3) O serviço ainda está inicializando (aguarde 30 segundos).
✔
Solução passo a passo
bash
# 1. Confirmar que o cluster está rodando $ jps # Deve mostrar os 5 processos! # 2. Descobrir o IP real da máquina (para VMs) $ hostname -I # 3. Verificar se a porta está ouvindo $ sudo ss -tlnp | grep 9870 # 4. Teste rápido no terminal $ curl -s http://localhost:9870 | head -5

🟡
Erro: ResourceManager ou NodeManager não aparece no jps
Missão 6 — YARN
▾
Causa: O YARN falhou por memória insuficiente, configuração incorreta no yarn-site.xml, ou porque o start-yarn.sh não foi executado (confundido com start-dfs.sh que inicia apenas o HDFS).
✔
Solução — Iniciar o YARN separadamente e verificar memória
bash
# Garantir que o YARN foi iniciado $ start-yarn.sh # Aguardar e verificar $ sleep 10 && jps # Ver log se ainda falhar $ cat /usr/local/hadoop/logs/hadoop-hadoop-resourcemanager-*.log | tail -30 # Verificar memória disponível (mín. recomendado: 4GB) $ free -h
⚠️ O YARN precisa de pelo menos 2-4 GB de RAM livre para iniciar. Se a VM tiver menos que 4 GB de RAM, configure o VirtualBox/VMware para alocar mais memória.
🔵
Erro: No such file or directory ao usar hdfs dfs -put ou -mkdir
Missão 7 — HDFS
▾
Causa: O diretório pai não existe no HDFS. Os comandos HDFS não criam a hierarquia de diretórios automaticamente (ao contrário do mkdir -p do Linux). Você deve criar cada nível separadamente ou usar -p.
✔
Solução — Criar a estrutura de diretórios corretamente
bash
# Ver o que existe na raiz do HDFS $ hdfs dfs -ls / # Criar a estrutura completa usando -p (cria tudo de uma vez) $ hdfs dfs -mkdir -p /user/hadoop/dados # Confirmar $ hdfs dfs -ls /user/hadoop/ # Agora fazer o upload $ hdfs dfs -put ~/teste.txt /user/hadoop/dados/

Dica Geral — Como ler os logs do Hadoop para qualquer erro
Habilidade essencial
▾
Os logs são a primeira coisa a verificar quando algo não funciona. Eles contêm a causa exata do erro com muito mais detalhe do que qualquer mensagem no terminal.
📁
Localização dos logs
bash
# Listar todos os logs disponíveis $ ls /usr/local/hadoop/logs/ # Ver log do NameNode $ tail -50 /usr/local/hadoop/logs/hadoop-hadoop-namenode-$(hostname).log # Ver log do DataNode $ tail -50 /usr/local/hadoop/logs/hadoop-hadoop-datanode-$(hostname).log # Ver log do ResourceManager $ tail -50 /usr/local/hadoop/logs/hadoop-hadoop-resourcemanager-$(hostname).log # Buscar todos os erros de uma vez $ grep -i "FATAL\|ERROR" /usr/local/hadoop/logs/*.log | tail -20
🔄
Reinicialização limpa — quando nada funciona
Se você está travado e quer recomeçar do zero sem reinstalar o Hadoop, use esta sequência.
bash
# 1. Parar tudo $ stop-all.sh 2>/dev/null; sleep 2 # 2. Apagar dados do HDFS e logs antigos $ rm -rf ~/dfsdata/namenode/* ~/dfsdata/datanode/* ~/tmpdata/* $ rm -f /usr/local/hadoop/logs/* # 3. Formatar o NameNode $ hdfs namenode -format # 4. Iniciar tudo de novo $ start-dfs.sh && sleep 5 && start-yarn.sh # 5. Verificar — deve mostrar 5 processos $ jps
⚠️ Esta reinicialização limpa apaga todos os dados do HDFS. Use somente durante a fase de configuração inicial.

📁 Arquivos, Permissões e Download
CMD
wget https://downloads.apache.org/hadoop/...
wget
Web Get — ferramenta de linha de comando para baixar arquivos da internet via HTTP, HTTPS e FTP. Suporta downloads em background e retomada de downloads interrompidos.
URL
Endereço completo do arquivo a ser baixado. O arquivo é salvo no diretório atual com o mesmo nome que aparece no final da URL.
CMD
sudo tar xzf hadoop-3.3.6.tar.gz -C /usr/local/
tar
Tape ARchive — ferramenta para agrupar e compactar arquivos. Arquivos .tar.gz (também chamados de tarballs) são o formato padrão de distribuição de software no Linux.
x
eXtract — modo de extração. Descompacta e extrai os arquivos do pacote.
z
gzip — indica que o arquivo usa compressão gzip (.gz). Necessário para arquivos .tar.gz.
f
File — indica que o próximo argumento é o nome do arquivo a processar. Sempre deve ser a última flag antes do nome do arquivo.
-C /usr/local/
Change to directory — extrai os arquivos no diretório especificado em vez do diretório atual.
CMD
sudo chown -R hadoop:hadoop /usr/local/hadoop
chown
CHange OWNer — altera o dono (usuário e grupo) de arquivos e diretórios.
-R
Recursive — aplica a mudança em todos os arquivos e subdiretórios dentro do caminho especificado.
hadoop:hadoop
Formato usuário:grupo. Define o usuário proprietário e o grupo proprietário simultaneamente. Em Linux, cada arquivo pertence a um usuário e a um grupo.
CMD
chmod 600 ~/.ssh/authorized_keys
chmod
CHange MODe — altera as permissões de acesso de arquivos e diretórios.
600
Notação octal de permissões: 6 = leitura+escrita para o dono, 0 = sem permissão para o grupo, 0 = sem permissão para outros. O SSH recusa arquivos de chave com permissões mais abertas que 600 por motivos de segurança.
700 / 644 / 755
700: dono tem tudo, grupo e outros sem acesso. 644: dono lê+escreve, outros só leem. 755: dono tem tudo, outros podem ler e executar.
Tabela de permissões
# Cada dígito octal = dono | grupo | outros # Valor: r(4) + w(2) + x(1) = soma # Exemplos: chmod 700 ~/.ssh/ # rwx --- --- (só dono acessa) chmod 600 ~/.ssh/id_rsa # rw- --- --- (dono lê/escreve) chmod 644 ~/.ssh/id_rsa.pub # rw- r-- r-- (público pode ler) chmod 755 /usr/local/hadoop # rwx r-x r-x (outros executam)
CMD
readlink -f $(which java) | sed "s|/bin/java||"
which java
Localiza o executável java no PATH. Retorna algo como /usr/bin/java.
$(...)
Command substitution — executa o comando dentro dos parênteses e usa a saída como argumento do comando externo. É como "encaixar" um comando dentro de outro.
readlink -f
Resolve links simbólicos recursivamente até encontrar o arquivo real. O /usr/bin/java é um symlink — readlink -f revela o caminho verdadeiro.
| sed "s|/bin/java||"
O | (pipe) passa a saída do comando anterior para o sed. O sed com s|buscar|substituir| remove /bin/java do caminho, deixando apenas o diretório raiz da JVM (que é o JAVA_HOME).

Comandos SSH — Geração de Chaves e Autenticação
Missão 2
▾
CMD
ssh-keygen -t rsa -P '' -f ~/.ssh/id_rsa
Como funciona a autenticação por chave SSH: o comando gera um par de chaves matematicamente relacionadas — uma privada (fica no seu computador) e uma pública (pode ser distribuída). Qualquer dado cifrado com a chave pública só pode ser decifrado com a chave privada. Assim, o servidor desafia o cliente com um dado cifrado pela chave pública, e se o cliente consegue resolver (usando a privada), a identidade é provada — sem precisar de senha.
ssh-keygen
Ferramenta para gerar, gerenciar e converter chaves de autenticação SSH.
-t rsa
Type RSA — especifica o algoritmo criptográfico. RSA é o mais amplamente suportado. Alternativas modernas incluem -t ed25519 (mais rápido e seguro, mas o Hadoop aceita ambos).
-P ''
Passphrase vazia — define uma senha vazia para a chave privada. Em produção, é recomendado usar uma passphrase, mas como o Hadoop precisa conectar de forma automática (sem interação humana), deixamos vazia.
-f ~/.ssh/id_rsa
File — caminho onde a chave será salva. Gera dois arquivos: id_rsa (chave privada — nunca compartilhe!) e id_rsa.pub (chave pública — pode ser distribuída).
CMD
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
cat
conCATenate — lê e exibe o conteúdo de arquivos. Aqui usamos para ler a chave pública.
>>
Redirecionamento com append — adiciona a saída ao final do arquivo sem apagar o conteúdo existente. Diferente de > que sobrescreve o arquivo inteiro — perigoso se já houver outras chaves autorizadas.
authorized_keys
Arquivo lido pelo servidor SSH. Cada linha contém uma chave pública autorizada a se conectar. Se a chave pública do cliente bater com uma linha deste arquivo, a autenticação é aprovada sem senha.
CMD
ssh localhost
ssh
Secure SHell — cliente SSH para conectar em servidores remotos (ou locais) de forma segura e criptografada.
localhost
Apelido para o próprio computador (IP 127.0.0.1). Testar ssh localhost simula exatamente o que o Hadoop faz ao iniciar o cluster — conecta em si mesmo para lançar os serviços.

Comandos Hadoop — Controle do Cluster (start/stop/format)
Missão 6
▾
CMD
hdfs namenode -format
hdfs
Comando principal do HDFS. É o ponto de entrada para todos os comandos relacionados ao sistema de arquivos distribuído — tanto de administração quanto de operação de arquivos.
namenode
Sub-comando que gerencia o NameNode diretamente. Usado para operações administrativas como iniciar o namenode manualmente, verificar metadados ou formatar.
-format
Inicializa (formata) o sistema de arquivos do HDFS. Cria a estrutura de diretórios de metadados, define um clusterID único e prepara o NameNode para o primeiro uso. Use apenas uma vez!
⚠️ O que acontece internamente: o format cria um novo clusterID (ex: CID-a3f1b2c4-...). O DataNode armazena esse ID quando inicia. Se você formatar novamente, o NameNode ganha um ID novo, mas o DataNode ainda guarda o antigo — gerando o erro "Incompatible clusterIDs".
CMD
start-dfs.sh e stop-dfs.sh
start-dfs.sh
Script em $HADOOP_HOME/sbin/ que inicia, via SSH, os seguintes processos: NameNode (nó mestre dos metadados), DataNode (nó de armazenamento de dados) e Secondary NameNode (faz checkpoints periódicos dos metadados — não é um backup!).
stop-dfs.sh
Para os mesmos processos de forma ordenada. Garante que os dados em memória são descarregados para o disco antes de encerrar.
CMD
start-yarn.sh e stop-yarn.sh
start-yarn.sh
Inicia o ResourceManager (gerencia recursos de CPU e memória do cluster) e o NodeManager (monitora e executa containers de tarefas em cada nó). YARN é necessário para executar jobs MapReduce e outras aplicações no cluster.
CMD
jps
jps
Java Virtual Machine Process Status — lista todos os processos Java em execução com seus PIDs (identificadores de processo). Como todos os daemons do Hadoop são processos Java, jps é o comando padrão para verificar se o cluster está saudável.
O que cada processo faz
NameNode → Gerencia os metadados do HDFS (onde cada bloco está) DataNode → Armazena os blocos de dados reais no disco SecondaryNameNode→ Faz merge periódico dos logs do NameNode (checkpoint) ResourceManager → Aloca recursos (CPU/RAM) entre as aplicações YARN NodeManager → Executa containers de tarefas e reporta ao ResourceManager Jps → O próprio comando jps (aparece listado a si mesmo)

Comandos HDFS — Operações de Arquivos (hdfs dfs)
Missão 7
▾
Todos os comandos de arquivo do HDFS seguem o padrão hdfs dfs -<operação> [opções] <origem> [destino]. O dfs (Distributed File System Shell) aceita a maioria dos comandos que você já conhece do Linux (ls, mkdir, cat, rm), mas com o prefixo -.
🎓 Conexão com a disciplina (IAL008): A ementa descreve "Características e processamento de sistemas: estrutura de programação MapReduce, incluindo o mapa, classificação de ordem, ordem aleatória e componentes de redução". O HDFS é o sistema de entrada e saída do MapReduce — os dados são lidos do HDFS, processados pelo Map, embaralhados (shuffle), reduzidos e o resultado é gravado de volta no HDFS. Dominar os comandos hdfs dfs é pré-requisito para executar qualquer job MapReduce nas próximas semanas.
📋 ls, mkdir
CMD
hdfs dfs -ls /user/hadoop/dados/
dfs
Sub-comando do hdfs que abre o shell de sistema de arquivos distribuído — é por aqui que passam todos os comandos de leitura/escrita de arquivos e diretórios no HDFS.
-ls
Lista o conteúdo de um diretório no HDFS. A saída mostra: permissões, fator de replicação, dono, grupo, tamanho, data/hora e nome.
-ls -R
Recursive — lista também todo o conteúdo de subdiretórios.
Caminhos no HDFS
Sempre começam com /. São totalmente independentes do sistema de arquivos local — /user/hadoop/ no HDFS não tem nada a ver com /home/hadoop/ no Linux.
Lendo a saída do -ls
-rw-r--r-- 1 hadoop supergroup 68 2024-01-15 10:30 /user/hadoop/dados/teste.txt #permissões ^replicação dono grupo ^tamanho(bytes) caminho
CMD
hdfs dfs -mkdir -p /user/hadoop/dados
-mkdir
Cria um diretório no HDFS. Diferente do Linux, sem o -p falha se o diretório pai não existir.
-p
Parents — cria todos os diretórios da hierarquia que não existirem. Equivalente ao mkdir -p do Linux.
📤 put / get — Transferência de Dados
CMD
hdfs dfs -put ~/teste.txt /user/hadoop/dados/
-put
Copia arquivos do sistema local para o HDFS. Equivalente ao -copyFromLocal. O arquivo é dividido em blocos (padrão 128 MB), distribuído e replicado entre os DataNodes.
~/teste.txt
Caminho de origem — arquivo no sistema de arquivos local da máquina.
/user/hadoop/dados/
Caminho de destino — diretório no HDFS. Se terminar com /, o arquivo mantém o nome original.
Variações do put
hdfs dfs -put arquivo.txt /destino/ # upload simples hdfs dfs -put arquivo.txt /destino/novo-nome.txt # upload renomeando hdfs dfs -put *.csv /destino/ # upload de múltiplos arquivos hdfs dfs -put -f arquivo.txt /destino/ # -f força sobrescrever
CMD
hdfs dfs -get /user/hadoop/dados/teste.txt ~/baixado.txt
-get
Copia arquivos do HDFS para o sistema de arquivos local. O processo inverso do -put. O HDFS reúne os blocos distribuídos, monta o arquivo completo e entrega ao sistema local.
👁️ cat, tail, rm, df, du — Leitura, Exclusão e Espaço
CMD
hdfs dfs -cat /user/hadoop/dados/teste.txt
-cat
Lê e exibe o conteúdo de um arquivo do HDFS diretamente no terminal — sem precisar baixá-lo primeiro. Útil para arquivos de texto pequenos. Para arquivos grandes, use -tail.
-tail
Exibe apenas as últimas linhas do arquivo (padrão: 1 KB). Útil para verificar o fim de arquivos de log grandes sem baixar o arquivo inteiro.
CMD
hdfs dfs -rm -r /user/hadoop/dados/arquivo.txt
-rm
Remove arquivos do HDFS. Por padrão, envia para a lixeira (/user/hadoop/.Trash/) em vez de deletar imediatamente — isso permite recuperação acidental.
-r
Recursive — permite remover diretórios e todo o seu conteúdo. Sem o -r, o comando falha se o alvo for um diretório.
-skipTrash
Opção adicional que deleta imediatamente sem passar pela lixeira. Use com cuidado: não há recuperação!
CMD
hdfs dfs -df -h / e hdfs dfs -du -h /user/
-df
Disk Free — mostra o espaço total, utilizado e disponível no cluster HDFS como um todo.
-du
Disk Usage — mostra o espaço ocupado por cada arquivo/subdiretório dentro de um caminho. Útil para identificar o que está consumindo espaço.
-h
Human-readable — exibe os tamanhos em formato legível (KB, MB, GB) em vez de bytes brutos. Presente em ambos os comandos.
🔍 fsck — Diagnóstico de Blocos
CMD
hdfs fsck /user/hadoop/dados/teste.txt -files -blocks -locations
fsck
File System ChecK — verifica a integridade do sistema de arquivos e mostra informações detalhadas sobre como os arquivos estão armazenados no cluster.
-files
Exibe informações de cada arquivo analisado (nome, tamanho, status de saúde).
-blocks
Lista os blocos de cada arquivo, com o ID de cada bloco e o estado de replicação (Under replicated, Over replicated, OK).
-locations
Mostra em quais DataNodes cada bloco está armazenado. Fundamental para entender como a distribuição de dados funciona no HDFS.

Arquivos de Configuração XML — Propriedades e Valores
Missão 5
▾
O Hadoop usa arquivos XML para todas as suas configurações. Cada arquivo controla um módulo diferente. Entender cada propriedade é essencial para diagnosticar problemas e ajustar o comportamento do cluster.
core-site.xml — Configurações Gerais do Hadoop
hadoop.tmp.dir
Diretório base para arquivos temporários de todos os módulos do Hadoop. O NameNode e DataNode usam este caminho como base para criar suas estruturas de dados se não forem especificados caminhos próprios.
fs.default.name
(ou fs.defaultFS)
URI do sistema de arquivos padrão. O prefixo hdfs:// indica que é um sistema de arquivos HDFS (não local). localhost:9000 é o endereço e porta onde o NameNode vai ouvir conexões RPC (chamadas remotas).
hdfs-site.xml — Configurações do HDFS
dfs.data.dir
Caminhos no sistema local onde o NameNode e o DataNode vão gravar seus dados. O NameNode armazena metadados (quais blocos existem e onde estão). O DataNode armazena os blocos de dados reais.
dfs.replication
Fator de replicação — quantas cópias de cada bloco o HDFS deve manter. Em produção o padrão é 3 (tolerância a falha de 2 nós). Em pseudo-distribuído usamos 1 porque há apenas um DataNode — se colocássemos 3, o HDFS ficaria em estado Under replicated para sempre.
dfs.blocksize
(não configurado aqui)
Tamanho de cada bloco de dados. Padrão: 128 MB no Hadoop 3.x. Arquivos menores que 128 MB usam apenas um bloco. Um arquivo de 300 MB seria dividido em 3 blocos (128 + 128 + 44 MB).
mapred-site.xml — Configurações do MapReduce
mapreduce.framework.name
Define qual framework executa os jobs MapReduce. Valor yarn significa que o YARN gerencia a execução. Alternativa local executa tudo em um único processo Java (modo standalone, sem cluster).
yarn-site.xml — Configurações do YARN
yarn.nodemanager.aux-services
Serviços auxiliares que o NodeManager deve executar. O valor mapreduce_shuffle ativa o serviço de shuffle — responsável por transferir dados intermediários entre a fase Map e a fase Reduce.
...shuffle.class
Classe Java que implementa o serviço de shuffle. Deve sempre ser especificada junto com o aux-services.
yarn.resourcemanager.hostname
Endereço do nó que executa o ResourceManager. Em modo pseudo-distribuído é localhost. Em cluster real, seria o hostname ou IP do nó mestre.
